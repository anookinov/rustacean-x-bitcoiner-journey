Installing Ollama and Models

Ollama turns the AI VM into a local model server: it installs as a systemd service, exposes an OpenAI-compatible REST API on port 11434, and provides a simple CLI to pull and manage models. VS Code on my MacBook connects to this endpoint to run inference.

In this guide, you will:

  • Update Ubuntu and install prerequisites
  • Install Ollama and verify it starts as a systemd service
  • Configure Ollama to accept connections from your MacBook (not just localhost)
  • Pull code-focused open-source models
  • Test the REST API from your MacBook to confirm VS Code will be able to reach it

Pre-requisites

Preparation

  • AI VM provisioned and SSH-accessible from your MacBook (ssh ai@192.168.1.101)
  • Proxmox VM firewall rules in place (from Provisioning the AI VM)
  • Outbound HTTP/HTTPS allowed (for downloading Ollama and models)

Hardware

  • AI VM with at least 8 GB free RAM and 50+ GB free disk space
  • MacBook on the same LAN to test the REST API

Software

  • Ubuntu Server 24.04 LTS (installed in the AI VM)
  • curl (pre-installed on Ubuntu)

References

  • Ollama GitHub repository
  • Ollama model library
  • Ollama REST API documentation

Step-by-Step Instructions

Step 1: Update Ubuntu

SSH into the AI VM from your MacBook:

ssh ai@192.168.1.101

Update package lists and upgrade installed packages:

sudo apt update && sudo apt upgrade -y

Install useful tools you will need:

sudo apt install -y curl wget htop

Step 2: Install Ollama

Ollama provides an official install script that sets up the binary, systemd service, and the ollama user automatically:

curl -fsSL https://ollama.com/install.sh | sh

The script:

  • Downloads the Ollama binary to /usr/local/bin/ollama
  • Creates a system user ollama that runs the service
  • Installs a systemd service unit at /etc/systemd/system/ollama.service
  • Starts the service and enables it on boot

Verify the service is running:

sudo systemctl status ollama

Expected output includes Active: active (running). If the service is not running:

sudo systemctl start ollama
sudo systemctl enable ollama

Check that Ollama is listening on localhost:

curl http://localhost:11434
# Expected: Ollama is running

Step 3: Configure Ollama to Listen on All Interfaces

By default, Ollama listens only on 127.0.0.1 (localhost). To let VS Code on your MacBook reach it over the LAN, you need to configure it to listen on 0.0.0.0.

  1. Edit the Ollama systemd service override:

    sudo systemctl edit ollama

    This opens a drop-in override file in your editor. Add the following content between the two comment lines:

    [Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"

    Save and exit (Ctrl+O, Enter, Ctrl+X in nano).

  2. Reload systemd and restart Ollama:

    sudo systemctl daemon-reload
sudo systemctl restart ollama

  3. Verify Ollama is now listening on all interfaces:

    sudo ss -tlnp | grep 11434
# Expected: LISTEN  0  ...  0.0.0.0:11434  ...

🔒 Security Note: Ollama has no built-in authentication. It is only safe to expose on 0.0.0.0 because the Proxmox VM firewall (set up in the previous guide) restricts port 11434 to your MacBook’s IP only. Do not expose this port without the firewall rules in place.

Step 4: Pull Code-Focused Models

Pull the primary code model. This downloads the model weights to disk (~4.7 GB):

ollama pull qwen2.5-coder:7b

Download time depends on your internet connection. For a 500 Mbps connection, expect ~5–10 minutes.

Pull the planning/reasoning model (~4.7 GB):

ollama pull llama3.1:8b

List downloaded models to confirm:

ollama list

Expected output:

NAME                    ID              SIZE    MODIFIED
qwen2.5-coder:7b        ...             4.7 GB  just now
llama3.1:8b             ...             4.7 GB  just now

💾 Disk Usage: Each 7B model occupies roughly 4–5 GB of disk. With 100 GB allocated to the VM and Ubuntu using ~10 GB, you have space for 15–20 models. Pull only what you plan to actively use; ollama rm <model> removes a model when you no longer need it.

Step 5: Test Inference Locally

Run a quick test to confirm the model loads and produces output:

ollama run qwen2.5-coder:7b "Write a Rust function that reverses a string in place."

The first run loads the model into RAM (~5–10 seconds). You should receive a Rust code snippet in response. For CPU-only inference, expect the full response in 15–40 seconds for a short prompt.

Exit the interactive session with /bye or Ctrl+D.

Test the llama3.1:8b model:

ollama run llama3.1:8b "What are the key considerations when designing a multi-agent AI system?"

Step 6: Test the REST API from Your MacBook

From your MacBook Terminal (not the VM), verify that VS Code will be able to reach Ollama:

curl http://192.168.1.101:11434
# Expected: Ollama is running

Test a completion via the OpenAI-compatible API endpoint (the format Roo Code uses):

curl http://192.168.1.101:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen2.5-coder:7b",
    "messages": [{"role": "user", "content": "Say hello in Rust"}]
  }'

Expected: a JSON response with a choices array containing a Rust hello-world snippet. If the request times out, check that the Proxmox VM firewall Rule 2 (Ollama API from MacBook, port 11434) is enabled and that the Source IP matches your MacBook.

Step 7: Configure Automatic Model Management (Optional)

By default Ollama keeps a model loaded in RAM for 5 minutes after the last request, then unloads it. You can tune this if you want models to stay resident longer or unload faster:

  1. Add the environment variable to your Ollama service override:

    sudo systemctl edit ollama

  2. Update the override to include both variables:

    [Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
Environment="OLLAMA_KEEP_ALIVE=10m"

    OLLAMA_KEEP_ALIVE=10m keeps models loaded for 10 minutes after the last request — useful when you are actively coding and want fast response on subsequent requests. Set to 0 to unload immediately after each response if you need to conserve RAM.

  3. Reload and restart:

    sudo systemctl daemon-reload
sudo systemctl restart ollama

Troubleshooting

ollama: command not found after install:

  • The install script places the binary at /usr/local/bin/ollama. Confirm: ls -la /usr/local/bin/ollama. If missing, re-run the install script.

Service fails to start (systemctl status ollama shows failed):

  • Check logs: sudo journalctl -u ollama -n 50. A common cause is a port conflict. Verify nothing else is on port 11434: sudo ss -tlnp | grep 11434.

REST API unreachable from MacBook (connection refused or timeout):

  • Verify OLLAMA_HOST=0.0.0.0:11434 is set in the override: sudo systemctl cat ollama | grep OLLAMA_HOST
  • Verify Ollama is listening: sudo ss -tlnp | grep 11434 should show 0.0.0.0:11434
  • Verify the Proxmox firewall Rule 2 is enabled with the correct MacBook IP

Model pull fails mid-download:

  • Run ollama pull <model> again — pulls are resumable

Very slow inference (>60 seconds per response for a 7B model):

  • CPU-only inference at 8 vCPUs should produce ~10–20 tokens/second for a 7B model. Check CPU allocation in Proxmox and ensure the host CPU type is set (enables SIMD optimizations). Also verify no other VM is pegging the CPU: htop on the Proxmox host.
