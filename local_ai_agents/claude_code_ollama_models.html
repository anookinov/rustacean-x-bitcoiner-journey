Using Local Ollama Models with Claude Code

Claude Code sends every request to Anthropic’s Messages API by default. Since Ollama v0.14.0, Ollama natively speaks the Anthropic Messages API, so you can point Claude Code directly at your local Ollama instance with a single environment variable — no extra software required. If you hit a known stability issue with Ollama’s native endpoint, this guide also documents a LiteLLM Proxy fallback that is more robust.

In this guide, you will:

  • Try the native Ollama approach first — two environment variables, no extra software
  • Understand the known count_tokens limitation and how to detect it
  • Set up LiteLLM Proxy as a fallback when the native approach becomes unstable
  • Verify the connection end-to-end

Pre-requisites

Preparation

  • Ollama v0.14.0 or later running on the AI VM with at least one model pulled (e.g. qwen3:8b, deepseek-r1:8b)
  • autossh tunnel active (localhost:11434 → AI VM port 11434) — set up in Configuring VS Code Agent Extensions
  • Claude Code VS Code extension installed and authenticated with an Anthropic API key at least once (so the extension binary is in place)

Software

  • Native approach: nothing additional required
  • LiteLLM fallback: Python 3.9+ on the Mac

Approach 1 — Native Ollama (Start Here)

Ollama v0.14.0+ exposes a /v1/messages endpoint in Anthropic Messages API format. Claude Code connects directly with no translation layer.

Architecture (native)

┌──────────────────────────────────────────────────────────────────────┐
│  MacBook                                                             │
│                                                                      │
│  Claude Code (VS Code)                                               │
│  └── POST /v1/messages { model: "qwen3:8b", ... }                   │
│            │ Anthropic Messages API (native)                        │
│            ▼                                                         │
│  localhost:11434 — SSH tunnel endpoint                               │
│            │ autossh tunnel                                          │
│            ▼                                                         │
│  AI VM — Ollama v0.14.0+                                             │
│  └── /v1/messages (native Anthropic endpoint)                        │
└──────────────────────────────────────────────────────────────────────┘

Step 1: Pull Models on the AI VM

SSH into the AI VM and pull whichever models you want to use:

ssh ai@192.168.1.101

ollama pull qwen3:8b
ollama pull deepseek-r1:8b
ollama pull qwen2.5-coder:7b
ollama pull gemma3:12b
ollama pull llama3.3:latest

Context window: Ollama defaults to a 2 048-token context window, which is too short for Claude Code’s long prompts. Set OLLAMA_NUM_CTX globally on the AI VM:

# In ~/.zshrc or the systemd unit that starts Ollama
export OLLAMA_NUM_CTX=32768

Restart Ollama after setting it: sudo systemctl restart ollama

Step 2: Set Environment Variables on the Mac

Add both variables to ~/.zshrc:

export ANTHROPIC_BASE_URL=http://localhost:11434
export ANTHROPIC_API_KEY=ollama   # any non-empty string; Ollama does not validate it

Reload the shell:

source ~/.zshrc

Shell restart required: VS Code inherits environment variables from the shell it was launched from. Close VS Code fully and relaunch it from a terminal — not the Dock — so it picks up the new variables:

source ~/.zshrc && code .

Step 3: Select a Model in Claude Code

Run /model inside the Claude Code panel and type the exact Ollama model name (e.g. qwen3:8b). Unlike the LiteLLM approach there is no alias mapping — the name must match the pulled model name exactly as shown by ollama list on the AI VM.

Step 4: Verify the Connection

Send a minimal test request mimicking what Claude Code sends:

curl http://localhost:11434/v1/messages \
  -H "x-api-key: ollama" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3:8b",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Reply with exactly: native working"}]
  }'

A response containing the model’s reply confirms the full chain: Claude Code → SSH tunnel → AI VM Ollama.

Known Limitation: count_tokens Stability Issue

Claude Code periodically calls POST /v1/messages/count_tokens to estimate token usage. Ollama’s native Anthropic endpoint does not support this endpoint, and the resulting 404 can push Ollama into an error state that requires a service restart (Ollama issue #13949, open as of May 2026).

Symptom: Claude Code freezes mid-task, new requests hang indefinitely, and ollama ps on the AI VM shows the model stuck.

Recovery:

# On the AI VM
sudo systemctl restart ollama

If this happens repeatedly during normal Claude Code use, switch to Approach 2 — LiteLLM Proxy.

Approach 2 — LiteLLM Proxy (Fallback)

LiteLLM sits between Claude Code and Ollama, translating Anthropic Messages API requests into Ollama’s OpenAI-compatible format. It handles the count_tokens call gracefully and lets you alias Ollama model names to Claude model names so the /model picker shows familiar names.

Architecture (LiteLLM)

┌──────────────────────────────────────────────────────────────────────┐
│  MacBook                                                             │
│                                                                      │
│  Claude Code (VS Code)                                               │
│  └── POST /v1/messages { model: "claude-sonnet-4-6", ... }          │
│            │ Anthropic Messages API                                  │
│            ▼                                                         │
│  localhost:4000 — LiteLLM Proxy                                      │
│  └── Maps model name → Ollama model                                  │
│  └── Translates Anthropic format → OpenAI/Ollama format              │
│            │ OpenAI-compatible API                                   │
│            ▼                                                         │
│  localhost:11434 — SSH tunnel endpoint                               │
│            │ autossh tunnel                                          │
│            ▼                                                         │
│  AI VM — Ollama                                                      │
│  └── /v1/chat/completions (OpenAI-compatible)                        │
└──────────────────────────────────────────────────────────────────────┘

Step 1: Install LiteLLM Proxy

pip install 'litellm[proxy]'

Verify the install:

litellm --version

Step 2: Create the LiteLLM Config

Create the config directory:

mkdir -p ~/.config/litellm

Write ~/.config/litellm/config.yaml:

model_list:
  # model_name must exactly match what Claude Code sends in the request body
  - model_name: claude-sonnet-4-6
    litellm_params:
      model: ollama_chat/qwen3:8b
      api_base: http://localhost:11434
      num_ctx: 32768

  - model_name: claude-opus-4-7
    litellm_params:
      model: ollama_chat/deepseek-r1:8b
      api_base: http://localhost:11434
      num_ctx: 16384

  - model_name: claude-haiku-4-5-20251001
    litellm_params:
      model: ollama_chat/qwen2.5-coder:7b
      api_base: http://localhost:11434
      num_ctx: 32768

litellm_settings:
  drop_params: true   # silently strips Anthropic-only params Ollama does not support

drop_params: true: Claude Code sends Anthropic-specific fields like cache_control and thinking that Ollama does not understand. This drops them silently rather than returning a 400 error.

Finding the exact model name: If Claude Code returns a model-not-found error, run LiteLLM in the foreground and watch the log — it prints the incoming model field on every request. Copy that exact string into model_name.

Step 3: Start the LiteLLM Proxy

For a foreground test run:

litellm --config ~/.config/litellm/config.yaml --port 4000

For a persistent background process:

nohup litellm --config ~/.config/litellm/config.yaml --port 4000 \
  &> ~/.config/litellm/proxy.log &
echo $! > ~/.config/litellm/proxy.pid

To stop the background process later:

kill $(cat ~/.config/litellm/proxy.pid)

Step 4: Point Claude Code at the Proxy

Update ~/.zshrc:

export ANTHROPIC_BASE_URL=http://localhost:4000
export ANTHROPIC_API_KEY=sk-litellm-local   # any non-empty string; LiteLLM does not validate it

Reload and relaunch VS Code:

source ~/.zshrc && code .

Step 5: Verify the Proxy

Confirm the proxy is reachable:

curl http://localhost:4000/health

Then send a test request:

curl http://localhost:4000/v1/messages \
  -H "x-api-key: sk-litellm-local" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Reply with exactly: proxy working"}]
  }'

Swapping Models (LiteLLM)

To change which Ollama model backs a Claude Code model name, edit ~/.config/litellm/config.yaml and restart the proxy:

kill $(cat ~/.config/litellm/proxy.pid)
nohup litellm --config ~/.config/litellm/config.yaml --port 4000 \
  &> ~/.config/litellm/proxy.log &
echo $! > ~/.config/litellm/proxy.pid

Known Limitations

Claude Code is designed around Anthropic model capabilities. When running on Ollama:

  • Tool-use quality varies — Claude Code relies heavily on tools (file reads, bash, MCP). Models trained for tool use (qwen2.5-coder, qwen3, llama3.1+) work best; models without explicit tool-use training cannot reliably produce the structured JSON Claude Code expects
  • Extended thinking is silently ignored — the thinking parameter is dropped at the Ollama layer; the model does not chain-of-thought unless it has built-in reasoning (like deepseek-r1)
  • Smaller effective context — even with OLLAMA_NUM_CTX=32768, local models fall far short of Claude’s 200k-token window; very large repos or long conversations may hit the limit mid-task
  • Slower interactive features — local CPU inference produces 10–25 tokens/second; inline completions and quick fixes feel slower than with hosted Claude

Troubleshooting

Claude Code freezes mid-task (native approach)

Ollama is in an error state from the count_tokens call. Restart Ollama on the AI VM, then consider switching to the LiteLLM fallback:

sudo systemctl restart ollama

Connection refused on port 11434 or 4000

The autossh tunnel is down. Re-establish it:

autossh -M 20001 -f -N -L 11434:localhost:11434 ai@192.168.1.101

If using LiteLLM, also check that the proxy is running:

litellm --config ~/.config/litellm/config.yaml --port 4000

Model not found (LiteLLM)

The model name Claude Code sent does not match any model_name in the config. Run LiteLLM in the foreground, trigger a request from Claude Code, and copy the exact model string from the log into a new model_name entry.

Claude Code still calls Anthropic

ANTHROPIC_BASE_URL is not in the environment VS Code was launched from. Relaunch from a terminal that has the variable set:

source ~/.zshrc && code .

Tool-use errors or malformed function_calls JSON

Switch to a model with stronger tool-use support (qwen3:8b, qwen2.5-coder:7b, llama3.1+). Models without explicit tool-use training cannot reliably produce the structured output Claude Code expects.

Reverting to Anthropic Claude

To switch Claude Code back to the official Anthropic API, undo the two environment variable changes and (if running) stop the LiteLLM proxy.

Step 1: Remove the Ollama Environment Variables

Open ~/.zshrc and delete (or comment out) these two lines:

# Remove or comment out both of these:
export ANTHROPIC_BASE_URL=http://localhost:11434   # or :4000 for LiteLLM
export ANTHROPIC_API_KEY=ollama                    # or sk-litellm-local

Then restore your real Anthropic API key:

export ANTHROPIC_API_KEY=sk-ant-...   # your actual Anthropic API key

Reload the shell:

source ~/.zshrc

Step 2: Stop the LiteLLM Proxy (if running)

If you started a background LiteLLM process, stop it:

kill $(cat ~/.config/litellm/proxy.pid)

If there is no PID file, find and kill the process by name:

pkill -f "litellm"

Step 3: Relaunch VS Code

VS Code inherits environment variables from the shell it was launched from. Close VS Code fully and relaunch from a terminal so it picks up the restored variables:

source ~/.zshrc && code .

Step 4: Select an Anthropic Model

Run /model inside the Claude Code panel and select or type an Anthropic model name (e.g. claude-sonnet-4-6, claude-opus-4-7). Claude Code will now route requests to api.anthropic.com using your real API key.

Verify: Send a test message and confirm the model name shown in the Claude Code header matches the Anthropic model you selected, not a local model name.

Maintaining Sovereignty in the Workflow

In both approaches, no code or prompts leave your local network:

  • Claude Code sends requests to localhost:11434 (native) or localhost:4000 (LiteLLM) — both on the Mac
  • Traffic flows through the SSH tunnel to the AI VM on the local LAN
  • Ollama performs inference on the AI VM’s GPU or CPU
  • No external API calls are made; the ANTHROPIC_API_KEY placeholder never reaches Anthropic

The only data that leaves the local network is the initial ollama pull when downloading model weights.
