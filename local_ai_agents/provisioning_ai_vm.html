Provisioning the AI VM on Proxmox

The AI agents VM runs on the same Minisforum hardware as the Bitcoin node — but in a separate Proxmox virtual machine with firewall rules that block it from reaching the Bitcoin node VM, the router admin interface, or any other LAN device. The MacBook is the only machine explicitly allowed to connect to it.

This separation enforces the principle that AI agents have no implicit access to my infrastructure. Access must be granted deliberately, one rule at a time.

In this guide, you will:

  • Create a new Ubuntu 24.04 LTS VM in Proxmox with resources sized for Ollama inference
  • Complete Ubuntu installation and configure SSH access from your MacBook
  • Apply Proxmox VM-level firewall rules to isolate the VM from the rest of your LAN
  • Verify the isolation is working before proceeding to install Ollama

Pre-requisites

Preparation

  • Proxmox VE running and accessible at https://192.168.1.100:8006
  • SSH key already set up on your MacBook (created during Securing Proxmox VE)
  • Ubuntu 24.04 LTS ISO uploaded to Proxmox local storage, or internet access to upload it now
  • Your MacBook’s LAN IP address (check with ipconfig getifaddr en0 in Terminal)

Hardware

  • Minisforum X1-255 running Proxmox VE with at least 16 GB free RAM
  • The Bitcoin node Start9 VM running normally (you will verify isolation against it)

Software

  • Proxmox VE web interface (Safari, Chrome, or Firefox)
  • Ubuntu Server 24.04 LTS ISO (ubuntu.com/download/server)
  • SSH client (Terminal on macOS)

References

  • Ubuntu Server 24.04 LTS Release Notes
  • Proxmox VE Firewall Documentation

Step-by-Step Instructions

Step 1: Upload Ubuntu Server ISO to Proxmox

If you already have a Ubuntu Server ISO in Proxmox local storage, skip to Step 2.

  1. Download Ubuntu Server 24.04 LTS ISO on your MacBook:

    • Visit ubuntu.com/download/server
    • Download the latest Ubuntu Server 24.04 LTS ISO
    • File will be saved to ~/Downloads/ubuntu-24.04.x-live-server-amd64.iso

  2. Log in to the Proxmox web interface: https://192.168.1.100:8006

  3. Navigate to Datacenter → pve (your node) → local storage → ISO Images tab

  4. Click Upload, select the Ubuntu ISO, and wait for the upload to complete (~3–5 minutes)

Step 2: Create the AI Agents VM

  1. Click Create VM in the top right of the Proxmox web interface

  2. General tab — set VM identity:

    • VM ID: 101 (or next available; Start9 VM is typically 100)
    • Name: ai-agents
    • Leave Resource Pool and Start after created at defaults for now

  3. OS tab — select the Ubuntu ISO:

    • Use CD/DVD disc image file (iso)
    • Storage: local
    • ISO image: select ubuntu-24.04.x-live-server-amd64.iso
    • Guest OS Type: Linux
    • Version: 6.x - 2.6 Kernel (or latest available)

  4. System tab — leave all defaults:

    • Graphic card, Machine, BIOS, and SCSI Controller at defaults
    • Leave Qemu Agent unchecked (install it later if desired)

  5. CPU tab — allocate CPU cores:

    • Sockets: 1
    • Cores: 8
    • Type: host (enables CPU-specific optimizations, important for llama.cpp SIMD performance)

    🖥️ Core Allocation: The Minisforum X1-255 has 10 CPU cores. The Start9 VM uses 4, and Proxmox host reserves ~1–2. Allocating 8 cores to the AI VM is safe for most workloads; Proxmox overcommits CPU time so actual contention is low when the Bitcoin VM is idle.

  6. Memory tab — allocate RAM:

    • Memory (MiB): 16384 (16 GB)
    • Leave Minimum memory blank (no ballooning needed; Ollama needs stable RAM)

    💾 RAM Allocation: Start9 VM uses 6 GB, Proxmox host uses ~2 GB. With 32 GB total, allocating 16 GB to the AI VM leaves 8 GB of headroom — sufficient buffer for the host and future VMs.

  7. Disks tab — set up storage:

    • Bus/Device: SCSI 0
    • Storage: local-lvm
    • Disk size (GiB): 100
    • Cache: Default
    • SSD emulation: enable (check the box)
    • I/O thread: enable

    💽 Disk Sizing: 100 GB accommodates Ubuntu (~10 GB), several 7B Ollama models (~5–10 GB each), and working space. Each additional model you pull consumes 4–10 GB of disk.

  8. Network tab — connect to the main bridge:

    • Bridge: vmbr0 (same LAN bridge as the Start9 VM)
    • Model: VirtIO
    • Firewall: checked (enables Proxmox VM-level firewall — required for isolation steps below)
    • Leave MAC address as auto-generated

  9. Confirm tab — review, then click Finish

    Do not check “Start after created” yet — complete the ISO boot and install first by starting it manually from the VM view.

Step 3: Install Ubuntu Server

  1. In the Proxmox left sidebar, select your new ai-agents VM → click Console tab

  2. Click Start (▶) to power on the VM

  3. In the Console, you will see the Ubuntu Server installer boot menu:

    • Select Try or Install Ubuntu Server (first option, highlighted by default)
    • Press Enter

  4. Work through the Ubuntu Server installation wizard:

    Language: Select English (or your preference)

    Installer update: Choose Continue without updating (you will update after install)

    Keyboard: Select your layout

    Installation type: Select Ubuntu Server (not minimized)

    Network: DHCP is fine — Ubuntu will get an IP from your router automatically

    Proxy: Leave blank unless you use a proxy

    Ubuntu archive mirror: Leave as default (archive.ubuntu.com)

    Guided storage configuration:

    • Select Use an entire disk
    • Select the 100 GB virtual disk (the only available disk)
    • Leave Set up this disk as an LVM group checked
    • Proceed through the storage summary and confirm

    Profile setup — set your Ubuntu user:

    • Your name: (your name)
    • Server name: ai-agents
    • Username: ai (or your preferred username)
    • Password: strong password (20+ characters; store in your password manager)

    Ubuntu Pro: Skip (select Skip for now)

    SSH setup:

    • Check Install OpenSSH server
    • Leave Import SSH identity blank (you will copy your key manually)

    Featured server snaps: Deselect all (you will install only what you need)

  5. Installation runs for ~5–10 minutes. When complete, select Reboot Now

  6. When prompted, press Enter to eject the virtual CD (Proxmox handles this automatically for VMs)

  7. Ubuntu boots to a login prompt in the Console

Step 4: Copy Your SSH Key to the AI VM

  1. Find the AI VM’s IP address:

    • In Proxmox, select ai-agents → Summary tab → look for the IP under IPs
    • Or check your router’s DHCP leases

  2. From your MacBook Terminal, copy your existing SSH key:

    # Use the same key you set up for Proxmox access
ssh-copy-id -i ~/.ssh/id_ed25519.pub ai@192.168.1.XXX
# Replace XXX with the AI VM's IP

    Enter the Ubuntu password you set during installation when prompted.

  3. Test key-based login:

    ssh ai@192.168.1.XXX
# Should log in without a password prompt

  4. Assign a static IP via your router’s DHCP reservation for the AI VM’s MAC address. This prevents the IP from changing on reboot and ensures your VS Code and firewall rules stay valid.

    • Find the MAC address: from the Console or Proxmox ai-agents → Network tab
    • In your router admin interface, add a DHCP reservation for this MAC → assign a fixed IP (e.g., 192.168.1.101)
    • Reboot the AI VM and confirm it gets the reserved IP: ssh ai@192.168.1.101

🌐 Static IP Tip: Your router (AT&T BGW320) supports DHCP reservations under Home Network → IP Allocation. Pinning the AI VM to a fixed LAN IP is important: firewall rules and VS Code provider settings reference this IP by address, so it must not change.

Step 5: Configure VM-Level Firewall in Proxmox

This step applies firewall rules to the ai-agents VM itself — separate from the Datacenter-level firewall that protects Proxmox. These rules control what traffic the AI VM can send and receive.

Goal: The AI VM can be reached from your MacBook (for SSH and Ollama API) and can reach the internet (to pull models). It cannot reach the Bitcoin node VM, the router admin interface, or any other LAN device.

  1. In Proxmox, select ai-agents VM → Firewall tab → Options

  2. Double-click Firewall and set it to Yes to enable the VM-level firewall

  3. Set the default policies:

    • Double-click Input policy → set to DROP
    • Double-click Output policy → set to ACCEPT initially (you will restrict outbound next)

  4. Click Add to create inbound rules. Add these rules in order:

    Rule 1 — SSH from MacBook:
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: 192.168.1.XXX   ← your MacBook's static/reserved LAN IP
- Dest. port: 22
- Comment: SSH from MacBook

    Rule 2 — Ollama API from MacBook:
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: 192.168.1.XXX   ← your MacBook's LAN IP
- Dest. port: 11434
- Comment: Ollama REST API from MacBook

  5. Test that SSH still works from your MacBook after enabling the firewall:

    ssh ai@192.168.1.101
# Must succeed — if not, double-check the Source IP in Rule 1

  6. Now restrict outbound traffic to prevent the AI VM from reaching other LAN devices:

    Change Output policy to DROP, then add these outbound ACCEPT rules:

    Rule 3 — DNS (required for model downloads):
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: udp
- Dest. port: 53
- Comment: DNS resolution

    Rule 4 — Block HTTP/HTTPS to LAN (isolation):
- Enable: ☑
- Direction: out
- Action: DROP
- Protocol: tcp
- Destination: 192.168.1.0/24
- Dest. port: 80,443
- Comment: Block HTTP/HTTPS to LAN — prevents AI VM reaching Start9 or router admin

    Rule 5 — HTTP/HTTPS (required for Ollama model downloads):
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: tcp
- Dest. port: 80,443
- Comment: Internet HTTP/HTTPS for model downloads

    Rule 6 — NTP (required for clock sync):
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: udp
- Dest. port: 123
- Comment: NTP time sync

    🛡️ Outbound Restriction: With Output policy DROP, Rule 4 explicitly drops TCP 80/443 to the entire LAN subnet (192.168.1.0/24) — this blocks the AI VM from reaching the Start9 Bitcoin node VM or the router admin page over HTTP/HTTPS. Rules 5 and 6 then allow those same ports to internet destinations, so Ollama can still pull models. Rule ordering matters: Proxmox evaluates rules top-to-bottom, first match wins, so the LAN DROP must appear before the broad internet ACCEPT.

  7. Verify isolation — from inside the AI VM, these should all fail:

    # Attempt to reach the Bitcoin node VM (Start9)
# Replace 192.168.1.102 with your Start9 VM's actual IP
ping 192.168.1.102
# Expected: no response (packets dropped)

curl http://192.168.1.102:80
# Expected: connection timed out (blocked by Rule 4)

# Verify internet still works (needed for model downloads)
curl -s https://ollama.com | head -5
# Expected: HTML content returned

Troubleshooting

SSH connection refused after enabling firewall:

  • The Input policy is DROP and Rule 1 may not be matching. Check: Enable is ☑, the Source IP exactly matches your MacBook’s LAN IP, and port is 22. Temporarily disable the firewall in Options → Firewall → No, fix the rule, re-enable.

Ollama API unreachable from VS Code:

  • Check Rule 2 is present and enabled. Verify the Source IP matches your MacBook. Confirm Ollama is actually listening on 0.0.0.0:11434 (covered in the next guide).

AI VM cannot pull models after outbound DROP policy:

  • Verify Rules 3 and 4 are present and enabled. Test with curl https://ollama.com from inside the VM. If DNS fails, check Rule 3 (port 53 UDP).

IP address changed after reboot:

  • Set up a DHCP reservation in your router for the AI VM’s MAC address as described in Step 4.
