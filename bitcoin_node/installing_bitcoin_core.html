Rustacean X Bitcoiner Journey

Installing Bitcoin Core

This guide provides step-by-step instructions to install and configure Bitcoin Core on your Start9 OS instance. Running your own Bitcoin Core node gives you complete sovereignty over your Bitcoin transactions and eliminates trust in third parties.

In this guide, you will:

  • Access the Start9 Marketplace
  • Install Bitcoin Core
  • Configure node settings
  • Monitor blockchain sync
  • Enable port forwarding (optional)
  • Connect other services

Pre-requisites

Preparation

  • Start9 OS installed and accessible via web interface
  • Initial Start9 setup wizard completed
  • Master password set during initial setup

Hardware

  • Start9 OS device (native or Proxmox VM)
  • At least 600GB free storage space
  • MacBook or desktop for access

Software

  • Start9 OS running
  • Web browser (Safari, Chrome, Firefox, etc.)

References

  • Bitcoin Core Documentation
  • Start9 Bitcoin Core Guide

Step-by-Step Instructions

Step 1: Access Start9 Marketplace

Bitcoin Core is the reference implementation of a Bitcoin full node. It validates all transactions, enforces consensus rules, provides privacy, supports the network, and enables Lightning.

  1. Open your web browser
  2. Navigate to your Start9 web interface:
    • Local access: https://xxx-yyy.local (replace with your device name)
    • IP access: https://192.168.1.101 (use your Start9 IP address)
  3. Log in with your Start9 master password

Step 2: Browse and Install Bitcoin Core

  1. Click on Marketplace in the left sidebar
  2. Search for “Bitcoin Core” in the search bar
  3. Locate Bitcoin Core in the results
  4. Click on Bitcoin Core to open the service details
  5. Review the service description and requirements
  6. Click Install button
  7. Wait for the download and installation to complete (~2-5 minutes)

🌐 Marketplace Help: If you don’t see Bitcoin Core, ensure you’re connected to the internet and refresh the marketplace.

Step 3: Configure Bitcoin Core

After installation completes:

  1. Select the Bitcoin Core service in the Services list.

  2. For first-time setup, click Status → Configure. For future changes, use Menu → Config to access Bitcoin Core settings.

  3. Review and adjust the configuration options as shown in the screenshot below. Available config settings include (suggested values in parentheses):

    • RPC Settings (RPC configuration options)
      • Enable (Allow remote RPC requests) (On — required for Start9 web portal to connect; do not expose to the public internet)
      • Username (custom, not default) — Set a strong, unique username for security.
      • RPC Password (custom, not default) — Set a strong, unique password for security.
      • Advanced:
        • Authorization (default; nothing is added)
        • RPC Server Timeout (30s)
        • Threads (16) — Increase for high-performance or multi-user environments.
        • Work Queue (128 requests) — Default is fine unless you have many concurrent RPC calls.
    • ZeroMQ Enabled (On for service integrations)
    • Transaction Index (On — default) — Recommended for full nodes with sufficient storage (pruning disabled). Required for Mempool, Electrum, and other advanced services. Leave enabled if you plan to install these or want full transaction search capabilities.
    • Cointstat Index (Off unless required by another service)
    • Wallet
      • Enable Wallet (On if you want to use the built-in wallet)
      • Avoid Partial Spends (On)
      • Discard Change Tolerance (0.0001 BTC/kB)
    • Advanced
      • Mempool
        • Persist Mempool (On)
        • Max Mempool Size (300 MiB)
        • Mempool Expiration (336 hours)
        • Enable Full RBF (On) — Recommended for modern wallets and fee flexibility.
        • Permit Bare Multisig (On) — Only disable for strict policy or privacy reasons.
        • Relay OP_RETURN Transactions (On)
        • Max OP_RETURN Size (83 bytes)
      • Peers
        • Make public (On if you want to help the network)
        • Disable Peer Discovery (Off)
        • Disable Clearnet (Off)
        • Use V2 P2P Transport Protocol (On)
        • Add Nodes (leave blank unless connecting to specific peers; nothing is added)
      • Pruning Mode (Automatic) — Use Automatic for most users; set a custom value if you need to limit disk usage.
        • Max Chain Size (550 MiB) — Minimum for pruned node; set higher for more history.
      • Database Cache (5000 MiB) — Higher cache improves performance if you have RAM available.
      • Database Batch (33554432 bytes) — Default is fine for most users.
      • Block Filters
        • Compute Compact Block Filters (BIP158) (On for Electrum)
        • Serve Compact Block Filters to Peers (BIP157) (Off) — Enable only if you want to serve filters to other clients.
      • Bloom Filters (BIP37)
        • Serve Bloom Filter to Peers (Off unless needed by a wallet)
  1. Click Save to apply configuration

Step 4: Start Bitcoin Core

  1. After configuration is saved, click Start button
  2. Confirm you want to start the service
  3. Wait for the service to initialize (~30 seconds)

Step 5: Monitor Initial Blockchain Download (IBD)

Bitcoin Core must download and verify the entire blockchain history:

  1. Click on Bitcoin Core in the Services list
  2. Navigate to Logs or Status tab
  3. Monitor synchronization progress

IBD Progress Indicators:

Progress: 15.23%
Current Height: 150,000
Best Block: 850,000
Verification Progress: 15.23%

Expected Timeline:

  • Day 1-2: Downloads blocks rapidly (10-30% per day)
  • Day 3-5: Verification slows (older blocks have more transactions)
  • Day 5-7: Final verification and indexing
  • Total: 1-7 days depending on hardware and connection

Network & Memory Activity:

  • Download: ~600GB total
  • Upload: Minimal during IBD
  • CPU: Moderate usage during verification
  • Memory: Typically 1–4 GB RAM used during sync (can be higher if database cache is increased)

Step 6: Verify Bitcoin Core is Running

Once IBD completes:

  1. Check service status shows Running
  2. Verify Synced indicator shows 100%
  3. Check peer connections (should be 8-125 peers)

Indicators of successful sync:

Status: Running
Synced: 100%
Peers: 45
Best Block: 850,000 (current tip)

Step 7: Enable Port Forwarding (Recommended)

After Bitcoin Core is installed and running, you should enable port forwarding on your router to allow inbound connections from the Bitcoin network:

  1. Access your router’s configuration page (see your router’s manual for details)
  2. Forward Port 8333 (TCP) to your Start9 node’s IP address (e.g., 192.168.1.101)
  3. Save and apply the changes
  4. Verify port is open by checking Bitcoin Core peer connections (should increase to 40-125)

Why port forwarding?

  • Supports the Bitcoin network
  • Helps new nodes sync faster
  • Increases network decentralization

🔒 Network Ports Explained:

  • RPC port 8332 (🔑): For remote commands (web portal, integrations). Keep this accessible only on your local network—do not forward to the internet.
  • P2P port 8333 (🌐): For Bitcoin network peer connections. This is the only port you will forward in Step 7 to help the network.
  • Enabling remote RPC does not expose your node to the public internet unless you manually forward port 8332 (not recommended).

Step 8: Verify Your Published IP Address

To check what IP address Bitcoin Core is advertising to the network:

Method 1: Check Bitcoin Core Logs (Optional But Recommended)

  1. Go to Bitcoin Core → Logs in Start9 interface

  2. Search for lines containing addr or Trying to listen on port

  3. Look for output like:

    
2025-01-15 10:23:45 Listening on port 8333
2025-01-15 10:23:46 Received addr from peer: 203.0.113.42:8333

Method 2: Use Bitcoin Core RPC (Advanced)

If you want to query Bitcoin Core directly via RPC (requires RPC credentials):

# Get RPC credentials from Start9 Bitcoin Core properties
# Then query from your MacBook:
curl -u rpc_user:rpc_password http://192.168.1.101:8332 \
  -d '{"jsonrpc":"1.0","id":"curltest","method":"getnetworkinfo","params":[]}' \
  -H 'content-type: application/json'

# Look for "localaddresses" section in the output
# It will show:
# "address": "192.168.1.101"      # (without port forwarding)
# "address": "203.0.113.42"       # (with port forwarding - your public IP)

Note: bitcoin-cli command won’t work via SSH to Start9 because Bitcoin Core runs in a container. Use the RPC method instead or check logs.

Method 3: Check External Services (Quick)

  1. Visit https://bitnodes.io/ (Bitcoin node explorer)
  2. Search for your public IP address (check at https://whatismyipaddress.com/)
  3. Status will show one of:
    • Unreachable ❌ (no port forwarding)
    • Reachable ✅ (port forwarding configured)

Understanding “Unreachable” Status (Normal Before Port Forwarding):

When your node shows as Unreachable on Bitnodes.io, it means:

  • Your Bitcoin Core node IS running
  • Your Bitcoin Core IS syncing the blockchain
  • Your Bitcoin Core IS connecting to other peers (outbound connections)
  • External nodes CANNOT initiate connections TO your node (inbound)

Implications:

AspectUnreachable (No Port Forwarding)Reachable (Port Forwarding)
Blockchain Sync✅ Works normally✅ Works normally
Broadcasting Transactions✅ Full nodes relay✅ Full nodes relay
Supporting Lightning✅ Works normally✅ Works normally
Network Support⚠️ Limited (outbound only)✅ Helps new nodes sync
Your Privacy✅ Better (hidden)⚠️ Public IP visible

Key Point: Your node still functions 100% for personal use (running Lightning, Electrum, etc.). The only thing you’re missing is helping OTHER nodes find and sync from you.

What to do next:

  1. If you have not already, see Step 7: Enable Port Forwarding to allow inbound connections (forward port 8333 to your node as needed).
  2. Wait 5–10 minutes for Bitcoin to re-advertise your node.
  3. Check Bitnodes.io again—should show Reachable ✅ if port forwarding is working.
  4. Peer count in Start9 should increase significantly.

What you should see:

  • Without port forwarding: Your local IP (192.168.1.101) appears in Start9 logs, Bitnodes shows “Unreachable”
  • With port forwarding: Your ISP’s public IP appears in Bitnodes shows “Reachable”, peer connections increase
  • Peer connections: Typically 8-30 outbound peers always, 40-125+ total with inbound connections

Troubleshooting:

  • If peers don’t increase after port forwarding, wait 5-10 minutes (Bitcoin needs time to advertise)
  • Check that port 8333 TCP is actually forwarded (test at canyouseeme.org)
  • Verify Bitcoin Core status shows “Public: Enabled” in configuration

Step 9: Configure Blockchain Pruning (Optional)

If storage is limited and you don’t need full blockchain:

  1. Stop Bitcoin Core service
  2. Go to Configure
  3. Enable Pruning Mode
  4. Set pruning size (minimum 550MB, recommended 10-20GB)
  5. Save and Restart

Warning: Pruning requires re-downloading and re-verifying the blockchain. Do this during initial setup, not after full sync.

Step 10: Test RPC Connection

Verify Bitcoin Core RPC is accessible:

  1. Go to Bitcoin Core → Menu → Properties
  2. Find RPC Credentials:

ℹ️ Default Credentials: If you did not change them, the default is RPC User: bitcoin, RPC Password: (auto-generated by Start9; see Properties page)


RPC URL: http://192.168.1.101:8332
RPC User: bitcoin
RPC Password: [auto-generated]
  1. Copy credentials for use with other services

Step 11: Check Blockchain Data

Verify blockchain storage:

  1. Go to Bitcoin Core → Menu → Properties
  2. Check Disk Usage: Should show ~600GB when fully synced
  3. Verify Synced Block Height: Should match current Bitcoin Block Height

You have now completed all the essential steps to install and configure your Bitcoin Core node on Start9 OS. Ongoing Maintenance and Improvement

If your Bitcoin node sync is slow, memory usage is high, or you need to enable features like transaction indexing (which requires pruning to be disabled), you may need to increase the memory and storage allocated to your Start9 VM in Proxmox VE.

Increasing Memory (RAM)

  1. In Proxmox VE, select your Start9 VM in the left sidebar.
  2. Click the Hardware tab.
  3. Select Memory and click Edit.
  4. For the MINISFORUM AI X1-255 (with 32GB DDR5 RAM), allocate 24,576 MiB to 28,672 MiB RAM to your Start9 VM. This ensures optimal performance for Bitcoin Core and all other apps, while leaving 4,096–8,192 MiB for Proxmox VE host overhead and system stability.
  5. Click OK.
  6. Restart the VM for the new memory allocation to take effect.

💡 Recommended: With 32GB RAM and only one main VM (Start9 OS), allocating 24,576–28,672 MiB to Start9 is ideal for running multiple Bitcoin apps and future-proofing your node.

Increasing Storage

  1. The MINISFORUM AI X1-255 comes with a 1TB NVMe SSD, which is suitable for most users running Proxmox VE and a single Start9 VM with all apps installed via Start9 OS.
  2. In Proxmox VE, select your Start9 VM.
  3. Click the Hardware tab.
  4. Select the disk (e.g., scsi0 or virtio0), click the Disk Action button, then select Resize. In the ‘Resize Disk’ popup, enter the Size Increment (GiB) to expand the disk if you add a larger SSD in the future.
  5. For most setups, allocate at least 800GB to the Start9 VM to ensure enough space for the Bitcoin blockchain, apps, and future growth. Leave the remainder for Proxmox VE and system overhead.
  6. Click Resize disk if expanding.
  7. In Start9 OS, expand the filesystem to use the new space:
    • Log in to the Start9 web interface.
    • Go to System → Monitor (under the Insights section), then check the Disk section for storage info.
    • Use the built-in disk expansion tool if available, and follow prompts to expand the root filesystem and use the new space.

💡 Recommended: With a 1TB SSD, allocate 800GB+ to your Start9 VM for blockchain and app data. This covers current needs and allows for future expansion. If you plan to run additional services or store large files, consider upgrading to a larger SSD (2TB+) in the future.

Restart and Verify

  • Restart the Start9 VM.
  • Check available memory and storage in the Start9 web interface (System → About or System → Storage).

ℹ️ Tip: Upgrading your VM’s resources can help with sync speed, reduce memory pressure, and enable features like transaction indexing (txindex) that require pruning to be disabled.

Option: Reclaim Used Space from Existing 1TB SSD (No New Physical Storage)

If you want to reclaim space on your existing 1TB internal SSD (for example, if old or unused VM disks are taking up space), you can safely delete those disks and reallocate the freed space to your current Start9 VM. This is useful if you want to maximize available storage without adding new hardware.

Steps:

  1. Shut down your Start9 VM in Proxmox VE.
  2. Detach and remove old/unused virtual disks:
    • In the Proxmox web UI, select your Start9 VM.
    • Go to the Hardware tab, select the old or unused disk (e.g., scsi1, virtio1, or similar), and click Detach.
    • After detaching, click Remove to delete the disk entry from the VM.
  3. Delete the unused disk image to reclaim space:
    • Go to Datacenter → Storage and select the storage pool (e.g., local-lvm).
    • Find the unused disk image (it may be listed as ‘Unused Disk’ or by VM ID) and delete it. This will free up space on your 1TB SSD.

⚠️ Disk Reclaim Safety: Always back up important data before deleting disks. Double-check you are removing the correct disk to avoid accidental data loss.

  1. (If needed) Re-add the ‘local-lvm’ storage to Proxmox:

    • In the Proxmox web UI, go to Datacenter → Storage → Add → LVM-Thin (or LVM if appropriate).
    • Select the correct volume group (usually local-lvm), give it a name, and confirm to re-add it to your storage list.

  2. Add a new virtual disk to your Start9 VM:

    • In the Proxmox web UI, select your Start9 VM.
    • Go to the Hardware tab, click Add → Hard Disk.
    • Choose the storage pool (e.g., local-lvm) where you reclaimed space, set the desired size, and select the disk type (scsi or virtio recommended).
    • Add the new disk to the VM.

  3. Change boot option to CD/DVD ISO and mount Start9 ISO image:

    • In the Proxmox web UI, select your Start9 VM.
    • Go to the Hardware tab, click Add → CD/DVD Drive (if not already present).
    • Select the Start9 OS ISO image from your Proxmox storage.
    • Go to the Options tab, set Boot Order to prioritize the CD/DVD drive.
    • Confirm changes.
    • Restart the Start9 VM to boot from the ISO image and begin installation or recovery as needed.

  4. Start the Start9 VM after reinstalling from ISO and expand the filesystem in Start9 OS:

    • After completing the Start9 OS installation or recovery from the ISO (see previous step), start the Start9 VM.
    • Log in to the Start9 web interface.
    • Go to System → Monitor (under the Insights section), then check the Disk section for storage info.
    • Use the built-in disk expansion tool if available, and follow prompts to expand the root filesystem and use the new space.

🛑 Storage Full Warning: If you experience issues with Bitcoin Core not starting or syncing, see Troubleshooting: “No space left on device” after syncing Bitcoin blockchain for solutions.

Troubleshooting: “No space left on device” after syncing Bitcoin blockchain

Initial Symptom:

  • The Bitcoin Core app in Start9 OS gets stuck in Starting… and never progresses to syncing or completing the blockchain download. This is often the first sign that your storage is full, even if no error is shown.

Explicit Error:

  • After you restart the Start9 OS VM in Proxmox VE, you may see a no space left on device error. This confirms that your VM or device storage is full.

Both symptoms require the same solutions below.

What causes this?

  • The Bitcoin blockchain (as of 2025) is 700–800GB and growing.
  • Start9 OS, apps, logs, and overhead require additional space (20–40GB+).
  • If your VM disk is 1TB or less, you may run out of space after a full sync, especially if running other apps or keeping old backups/logs.

Options to resolve

1. Free up space (temporary fix)

  • Delete old backups, logs, or unused apps from the Start9 web interface (look under System, Storage, or the app’s own settings page).
  • Remove unnecessary files via SSH if enabled.
  • This may only provide a short-term solution.

2. Expand with SSD storage (faster, more expensive, path to internal upgrade)

  • Add a new, larger SSD to your Proxmox host (internal NVMe or external USB 3.0/3.1 SSD).

3. Expand with HDD storage (slower, cheaper, path to NAS storage upgrade)

🗄️ HDD Storage Options: Best Value for Large, Reusable Storage

If you are comfortable with slower storage (for archival, blockchain, or NAS use), HDDs offer the best cost per TB and can be easily repurposed for Nextcloud, RAID-1, or other NAS storage in the future. There are two main approaches:

Option 1: Buy a NAS HDD and Enclosure (Modular, Flexible, RAID-Ready)

  • Buy a bare NAS-grade HDD (e.g., Seagate IronWolf, WD Red Plus) and a compatible USB 3.0/3.1 or SATA enclosure.
  • Example drives:
    • Seagate IronWolf 4TB NAS HDD
    • WD Red Plus 4TB NAS HDD
  • Choose larger capacities (6TB, 8TB, or more) as needed for future NAS/RAID-1 upgrades.
  • Pair with a quality enclosure (single or dual-bay for RAID-1, e.g., TerraMaster, ORICO, or similar brands).
  • This setup is ideal if you want to migrate the drive(s) into a dedicated NAS or RAID-1 box for Nextcloud or other self-hosted storage later.

Option 2: Buy an All-in-One External HDD (Plug-and-Play, Shuckable)

  • Purchase a pre-assembled external HDD with enclosure, such as the Seagate Expansion 24TB/26TB External USB 3.0 Desktop Hard Drive.
  • These are plug-and-play with Proxmox and can be used immediately for blockchain or archival storage.
  • When ready to upgrade, you can “shuck” (remove) the internal HDD and install it in a NAS or RAID-1 enclosure for Nextcloud or other uses.

🛠️ Shucking & Warranty: Shucking voids the Seagate warranty, but is a common, cost-effective upgrade path for large, reliable storage.

  • The internal drive is typically a Seagate Exos or similar enterprise-class model, compatible with most NAS/RAID systems.

Both options provide a clear path to future NAS/RAID-1 storage for Nextcloud or other self-hosted solutions. Choose based on your comfort with assembling enclosures (Option 1) or convenience and best value per TB (Option 2).

My Final Choice: I chose to buy the Samsung 990 PRO 2TB NVMe SSD for my MINISFORUM AI X1-255. This drive offers the best balance of speed, endurance, and reliability for running a full Bitcoin node and Start9 OS in a Proxmox VM.

Why this is best: The Samsung 990 PRO delivers top-tier Gen 4 performance, high endurance (1200 TBW), and proven compatibility with the MINISFORUM AI X1-255. Upgrading to this SSD ensures fast sync, responsive apps, and future-proof storage for blockchain and self-hosted services.

How to migrate Start9 OS and all app data to a new 2TB SSD (cleanest, most future-proof method):

🛑 Important: This method ensures all Start9 OS, apps, and data are on the new 2TB SSD, making future upgrades, backups, and migrations much simpler. The 1TB SSD is now free for Proxmox host use or other VMs.

If you are starting fresh:

  • You can skip the backup and restore steps below. Simply follow the instructions to install the 2TB SSD, prepare it in Proxmox, and perform a clean Start9 OS installation on the new disk.

If you need to migrate existing data:

  • In the Start9 web interface, go to System → Backup and create a full backup of your node, apps, and settings. Download the backup file to your computer or external drive.
  • After installing Start9 OS on the new disk, restore your backup from the web interface to recover your node, apps, and data.

Step-by-step for a clean install or migration:

  1. Shut down all running services and systems:

    • In the Start9 web interface, stop all running apps (including Bitcoin Core).
    • Go to System → Power → Shutdown to power off Start9 OS.
    • In Proxmox VE, select your Start9 VM and click the Stop button to fully power off the VM.
    • Once all VMs are off, shut down the Proxmox VE host if you plan to install the SSD physically.

  2. Physically install the new 2TB SSD:

    • Power off and unplug your MINISFORUM device.
    • Open the case, install the 2TB NVMe SSD in the M.2 slot, and reassemble the device.

  3. Prepare the 2TB SSD for Proxmox VM storage:

    • Power on the device and boot into Proxmox VE.
    • In the Proxmox web UI, go to Datacenter → Node → Disks and confirm the new SSD is listed.
    • Select the 2TB SSD, click Wipe Disk (if needed), then Initialize Disk with GPT.
    • Go to Datacenter → Node → LVM and click Create: Volume Group. Select the 2TB SSD and create a new volume group (e.g., vg-2tb).
    • (Optional) Go to Datacenter → Node → LVM-Thin and click Create: Thinpool. Select the new volume group and allocate ~1900–2000GB for the thin pool (e.g., data-2tb).
      • Only create an LVM-Thin pool if you want to use thin provisioning, fast snapshots, or plan to run multiple VMs/disks on this storage.
      • If you are dedicating the entire disk to a single VM disk, standard LVM is sufficient and simpler.

⚠️ Thin Provisioning Risk: LVM-Thin allows you to over-allocate space (thin provisioning), which is flexible but risky: if the physical disk fills up because thin-provisioned volumes use more space than is physically available, all VMs/disks on that pool can become read-only or fail. Monitor disk usage carefully if using LVM-Thin.

  1. Remove the old 1TB LVM-Thin pool and free up the 1TB SSD for Proxmox host use:

    • In the Proxmox web UI, go to Datacenter → Node → LVM-Thin and identify the existing 1TB LVM-Thin pool (e.g., local-lvm).
    • Make sure no VMs or disks are using this pool (detach and remove any VM disks if needed).
    • Select the LVM-Thin pool, click More → Destroy to delete it.
    • Go to Datacenter → Node → LVM, select the associated volume group from the 1TB SSD, and click More → Destroy to remove it (required if you want to recreate a new LVM or LVM-Thin pool on the 1TB SSD).
    • The 1TB SSD is now ready for new Proxmox VE storage, ISOs, or other VMs as needed.

💡 Tip: Always double-check that all important data is backed up before deleting or removing any disks or storage pools. Handle SSDs and device internals with care to avoid static damage.

  1. Create a new LVM or LVM-Thin storage pool on the 1TB SSD for Proxmox VE:

    • In the Proxmox web UI, go to Datacenter → Node → Disks and select the 1TB SSD.
    • Wipe the 1TB SSD or re-initialize it with GPT if you want to repurpose it for new Proxmox storage or VMs. This will remove all existing partitions (BIOS boot, EFI, LVM, etc.) and allow you to create new storage pools as needed.
    • After destroying the old LVM-Thin pool and LVM volume group, simply create a new volume group and LVM-Thin pool using the existing LVM partition.
    • Go to Datacenter → Node → LVM and click Create: Volume Group. Select the existing LVM partition on the 1TB SSD and create a new volume group (e.g., vg-1tb).
    • (Optional) Go to Datacenter → Node → LVM-Thin and click Create: Thinpool. Select the new volume group and allocate the desired size for the thin pool (e.g., data-1tb).

🗑️ Destructive Operation Warning: Only wipe or re-initialize the disk if you are certain you no longer need any data or partitions on it. This action is destructive and cannot be undone. Double-check that all important data is backed up before proceeding.

  1. Create a new Start9 VM disk on the 2TB SSD:

    • In the Proxmox web UI, select your Start9 VM (or create a new one if desired).
    • Go to the Hardware tab, click Add → Hard Disk.

🛑 Troubleshooting: Insufficient Free Space When Creating VM Disk

If you see an error like TASK ERROR: lvcreate 'start9/vm-100-disk-0' error: Volume group "start9" has insufficient free space (476932 extents): 486400 required., this means your LVM volume group does not have enough free space for the requested disk size. To resolve:

  1. Double-check the size of your LVM pool in Proxmox (Datacenter → Node → LVM). If it’s smaller than your SSD, you may need to:
    • Delete and recreate the volume group with a larger size.
    • Remove any unused logical volumes or snapshots.
  2. Make sure the volume group (VG) uses the full SSD capacity.
  3. When creating the VM disk, set the size to slightly less than the available space (e.g., 1800GB for a 2TB SSD, not 1900GB).
  4. If needed, destroy and recreate the volume group to use the full disk.

For more details, see Proxmox LVM documentation.

    • Go to the Options tab, set the Boot Order to prioritize the CD/DVD drive.
    • Start the VM and boot from the ISO to begin the Start9 OS installation.

  2. Restore your backup and verify:

    • After installing Start9 OS, log in to the web interface and restore your backup if you created one.
    • Go to System → Monitor → Disk to confirm the full 2TB is available for OS, apps, and data.
