Virtualized Start9 OS Setup Guide (Advanced)

This guide covers running Start9 OS as a virtual machine (VM) on a Linux host. Use this method if your hardware is incompatible with native Start9 OS installation, or if you want to run multiple services on one machine.

In this guide, you will:

  • Set up a Proxmox VE (Option A) or KVM/QEMU (Option B) host for Start9 OS
  • Configure VM resources and storage
  • Install and launch Start9 OS as a VM
  • Troubleshoot common virtualization issues

Pre-requisites

Preparation

  • Mini PC or server connected to router and power
  • Basic familiarity with Linux/web interfaces
  • SSH access capability

Hardware

  • Recommended: MINISFORUM X1-255 Mini PC (32GB RAM, 1TB SSD)
  • Wired Ethernet connection (e.g., UGREEN Cat 8 cable)
  • Monitor and keyboard (for initial setup)
  • Laptop/desktop for downloads and web access
  • USB drive (64GB+) for flashing ISOs

Software (Choose One)

  • Option A: Proxmox VE (Used in this guide)
    • Proxmox Virtual Environment 9.1 (web UI + CLI, free community edition)
  • Option B: Manual KVM/QEMU on Linux
    • Ubuntu Server 24.04 LTS or Debian 12
    • KVM/QEMU with libvirt (command-line management)
  • Web browser (Safari, Chrome, or Firefox)

References

  • Proxmox VE Documentation
  • Start9 OS Documentation

Step-by-Step Instructions -> Option A: Proxmox Virtual Environment

Proxmox VE is Start9’s recommended hypervisor for running Start9 OS. It provides an enterprise-grade web interface, built-in backup/restore, and is fully open-source.

Step 1: Download Proxmox ISO

  1. On your MacBook, download Proxmox VE 9.1:

    Option 1: Using your browser (Recommended for macOS)

    • Visit the Proxmox VE Downloads page
    • Click on “Proxmox VE 9.1 ISO Installer”
    • Click “Download” button
    • File will be saved to ~/Downloads/proxmox-ve_9.1-1.iso

    Option 2: Using curl (macOS command line)

# Download Proxmox VE (ISO)
cd ~/Downloads
curl -O https://enterprise.proxmox.com/iso/proxmox-ve_9.1-1.iso

# Verify download
ls -lh proxmox-ve_9.1-1.iso
# Expected size: ~1.83 GB
  1. (Optional) Verify the SHA256 checksum of the downloaded ISO:
shasum -a 256 proxmox-ve_9.1-1.iso
# Should match: 6d8f5afc78c0c66812d7272cde7c8b98be7eb54401ceb045400db05eb5ae6d22

Step 2: Flash Proxmox ISO to USB

  1. Flash to USB using Balena Etcher (installed from Flashing Start9 OS):

    • Open Balena Etcher application
    • Click “Flash from file” and select proxmox-ve_9.1-1.iso
    • Click “Select target” and choose your USB drive
      • Warning: This will erase the Start9 OS currently on the USB
      • Use the same USB drive from earlier, or use a different USB if you want to keep both ISOs
    • Click “Flash!” to begin writing Proxmox ISO to USB
    • Wait for flashing to complete (~5-10 minutes)
    • Balena Etcher will verify the flash automatically

Step 3: Install Proxmox on Minisforum

  1. Insert Proxmox USB into Minisforum

  2. Power on the Minisforum

  3. Enter BIOS setup:

    • Press DEL key immediately after power on (before Minisforum logo appears)
    • Look for “Boot” or “Boot Options” menu
    • Set USB as the first boot device (if not already set)
    • Save and exit BIOS

  4. Power off, then power on again - the system will boot from the Proxmox USB

  5. The Proxmox installer boot menu should appear with several options:

    • Install Proxmox VE (Graphical) - Recommended for first-time users (interactive graphical installer; selected and used in this guide)
    • Install Proxmox VE (Terminal UI) - Text-based installer with similar options
    • Advanced Options - For custom partitioning and other settings

  1. Select “Install Proxmox VE (Graphical)” (first option) - this opens the interactive installer

  2. Select the target disk and filesystem

    • Choose the internal SSD as the target harddisk (this will erase all data on it).
    • For Filesystem, select ext4 (recommended for single disk setups).
    • Leave storage and advanced parameters at their default values unless you have specific needs.
    • See below for Filesystem Options:
      • ext4 - Simple, low overhead, no RAID (best for single disk)
      • xfs - High performance, supports RAID0/1/10
      • zfs - Advanced, supports RAID0/1/10/Z1/Z2/Z3
      • btrfs - Modern, supports RAID0/1/10

🖲️ For Your Current Setup (1x 1TB SSD): Select ext4 filesystem for simplest option with lowest resource overhead. No RAID complexity needed for a single SSD.

🛤️ Future Upgrade Paths:

  • Adding 2nd SSD: Use btrfs with RAID1 (mirroring for redundancy)
  • 3+ SSDs at 2TB+: Use ZFS with Z2 (RAID6-like protection with superior data integrity)

Proxmox supports live storage migration (pvmove) if you need to change configurations later.

  1. Set location, time zone, and keyboard layout

    • Select your country, time zone, and keyboard layout as appropriate for your region.

  1. Set the administrator password and email address

    • Enter your email address (used for notifications and system alerts).
    • Create a strong password for the root account and confirm it.

🔑 Password Requirements:

  • Use at least 12 characters
  • Mix uppercase, lowercase, numbers, and symbols
  • Avoid common words or easy patterns
  • Store securely (you’ll need this to access Proxmox web console)

  1. Configure the management network

    • Select the management interface (nic0 is usually the Ethernet port with the cable connected from your router).
    • Enter a hostname (FQDN), e.g., pve.local.
    • Enter a static IPv4 address (e.g., 192.168.1.100/24) or choose DHCP.
    • Enter the gateway (usually your router’s IP, e.g., 192.168.1.254).
    • Enter DNS servers (use defaults or specify custom DNS if desired).

🌐 Network Configuration Tips:

  • The installer may show an IPv6 default; change to IPv4 to match your gateway.
  • For static IP, pick an unused address in your LAN’s range (e.g., 192.168.1.100/24).
  • Default gateway for AT&T BGW320 is 192.168.1.254.
  • Default DNS is pre-filled from AT&T; you can use these or specify your own.
  • See the guide for more details on network configuration and troubleshooting.

  1. Review the summary and start installation

    • Review all configuration values on the summary screen.
    • Confirm that all entries (disk, region, network, etc.) are correct.
    • When ready, click Install. Optionally, leave “Automatically reboot after successful installation” enabled.

  2. Installation takes ~10-15 minutes

  3. System reboots; remove USB drive

    Proxmox VE is now installed on the Minisforum’s internal SSD. The USB drive is no longer needed for booting and can be reused to flash the Start9 OS ISO in the next step.

  4. Reset BIOS boot sequence (optional but recommended)

    To prevent accidental USB boot in the future, set the boot order back to NVMe first:

    • Power off the Minisforum
    • Power on and press DEL immediately to enter BIOS
    • Go to Boot or Boot Options
    • Set NVMe (Proxmox disk) as the first boot device
    • Set USB as second (if you want USB fallback)
    • Save and exit BIOS
    • System will boot directly from Proxmox

  5. Access Proxmox web console:

    From your MacBook browser, navigate to Proxmox Web Console using https://192.168.1.100:8006 or use the hostname https://pve.local:8006

    Login credentials:

    • Username: root
    • Password: The password you created during installation as Proxmox administration password

🌐 Access Tip: You can use the hostname (e.g., https://pve.local:8006) or use IP address (e.g., https://192.168.1.100:8006) you configured for Proxmox earlier. If you used DHCP, check your router’s DHCP leases to find the assigned IP.

Step 4: Enable Proxmox VE No-Subscription Repository (Free Updates)

By default, Proxmox VE shows a subscription warning and only enables the enterprise repository. To receive updates without a paid subscription, enable the no-subscription repository using the GUI method:

  1. Log in to the Proxmox web interface

  2. In the left sidebar, select Datacenter, then your node, then Repositories

  3. Disable the enterprise repository (select the pve-enterprise line and click Disable)

  4. Click Add

  5. Select No-Subscription from the dropdown menu

    • All fields (URIs, Suites, Components) will populate automatically

  6. Click Add to confirm

  7. Go to Updates in the sidebar and click Refresh

  8. Click Upgrade to update from the free repository

    You now have access to free Proxmox VE updates without a paid subscription.

🛠️ Alternative Methods:

  • CLI Method: Use SSH or terminal to edit repository files directly (/etc/apt/sources.list.d/)
  • Manual Edit: Edit repository files via web shell under node → Shell
  • See Proxmox Package Repositories documentation for details

Step 5: Upload Start9 OS ISO to Proxmox

  1. Download Start9 OS stable release ISO:

    • Visit the Start9 OS GitHub Releases page
    • Download latest stable ISO to your MacBook (e.g., startos-0.3.5.1-39de098_x86_64.iso)

  2. In Proxmox web interface, navigate to Datacenter → pve (your node) → local storage

  3. Click ISO Images tab

  4. Click Upload button

  5. Select your Start9 stable ISO file and click Upload

    • Hash algorithm: Leave as None (optional integrity verification; not required for this upload)
    • Wait for upload to complete (~3-5 minutes depending on connection speed)

🔄 USB Transfer Option: Alternatively, flash ISO to USB drive (using your MacBook) and insert USB into Minisforum device running Proxmox to transfer the file

Step 6: Create the Virtual Machine

  1. In the Proxmox web interface, click Create VM (top right) to start the virtual machine creation wizard.
  2. Enter general information for your VM:
    • Set Node to your Proxmox server (e.g., pve).
    • Choose a VM ID (default is 100, or pick another if needed).
    • Enter a Name for your VM (e.g., start9-bitcoin-node).
    • Leave Resource Pool empty (not needed for a single VM).
    • Leave Add to HA unchecked (not needed unless you have a cluster).
  3. Select the Start9 OS ISO and operating system type:
    • In the OS tab, select Use CD/DVD disc image file (iso).
    • Set Storage to local.
    • Choose the ISO image you uploaded earlier (e.g., startos-0.3.5.1-39de098_x86_64.iso).
    • For Guest OS, set Type to Linux and Version to 6.x - 2.6 Kernel (or latest available).
  4. Configure the system hardware for the VM:
    • In the System tab, leave Graphic card, Machine, BIOS, and SCSI Controller at their defaults.
    • Leave Qemu Agent unchecked.
    • No changes needed for other options unless you have specific requirements.
  5. Allocate CPU resources for the VM:
    • In the CPU tab, set Sockets to 1 and Cores to 4 (recommended for a Bitcoin node).
    • Set Type to host to fully utilize your CPU features.
    • Leave Bandwidth at default (unlimited).
  6. Allocate memory for the VM:
    • In the Memory tab, set Memory (MiB) to 6144 (6 GB for Start9 OS).
    • Optionally set Minimum memory to 2048 for ballooning.
  7. Set up the VM’s virtual disk:
    • In the Disks tab, set Bus/Device to SCSI 0 (default).
    • Choose Storage as local-lvm (or your storage pool).
    • Set Disk size (GiB) to 1000 (1TB recommended; minimum 750GB if space is limited).
    • Set Cache to Default (or write through for safety).
    • Leave Discard unchecked.
    • Enable SSD emulation if using an SSD (recommended).
    • Keep I/O thread checked for better performance.
    • Leave Bandwidth at default.
  8. Configure the VM’s network connection:
    • In the Network tab, set Bridge to vmbr0 (default).
    • Set Model to VirtIO for best performance.
    • Leave MAC address as auto-generated.
    • Ensure No network device is unchecked (you need network access).
    • Leave VLAN tag empty.
    • Keep Firewall checked for basic security.
  9. Review and finalize the VM setup:
    • In the Confirm tab, review all your settings.
    • Check Start after created to boot the VM immediately after creation.
  10. Click Finish to create the VM.

Step 7: Install Start9 OS

  1. VM will automatically start and boot from the ISO

  2. Click Console tab to view the VM screen

    • You’ll see “Guest not running” message initially
    • Click Start now button to power on the VM

  3. Follow Start9 OS installation wizard (first stage):

    • Select the installation disk (the virtual disk matching your Disks tab allocation, e.g., 1TB)
    • Select Install StartOS as the installation type (not “Start Fresh”)
    • The system will display unmounting messages (normal during Live ISO eject phase)
    • Press ENTER to continue when prompted

  4. System will automatically reboot after installation (into Start9 Setup):

    • Wait for reboot to complete (~2-3 minutes)

  5. Complete Start9 OS Setup (second stage):

    • On the Start9 OS Setup screen, choose Start Fresh (Recover only if restoring from backup)
    • Select the installation disk again if prompted (same virtual disk as above)
    • Set your master password (enter and re-type to confirm)
    • Continue following the setup wizard prompts

  6. After Start9 OS setup completes:

    • Click Continue to Login when prompted.
    • Log in with the master password you just set.

  7. Remove the ISO:

    • In Proxmox, select your VM (start9-bitcoin-node).
    • Click Hardware tab.
    • Select the CD/DVD Drive.
    • Click Edit.
    • Select Do not use any media.
    • Click OK.
    • Why: Prevents the VM from booting the installer ISO again on future restarts and avoids keeping the live ISO mounted.

  8. Start9 OS is now running on the VM. You can restart the VM later if needed.

💽 VM Data Persistence: Start9 OS data persists in the VM disk; the VM can be stopped/restarted without data loss.

Step 8: Access Start9 OS Web Interface

Quick Access Summary for Proxmox VM:

The VM automatically obtains an IP from your router via DHCP. You can access Start9 OS in two ways:

  1. Via local hostname (easiest): Navigate to https://xxx-yyy.local from any device on your network (replace with your device’s hostname)
  2. Via direct IP: Find the VM’s IP in Proxmox Summary tab, then navigate to https://192.168.1.101 (for example, if your Start9 OS VM is assigned 192.168.1.101)

For ongoing maintenance and best practices, see the Ongoing Management → For Proxmox (Option A) section below.

High-Level Guidance -> Option B: KVM QEMU on Ubuntu Debian

🖥️ Virtualization Approach: This guide focuses on Proxmox VE (Option A) as the chosen approach. KVM/QEMU on Ubuntu/Debian is an alternative for users who prefer traditional Linux distributions as the host OS.

Considerations for KVM/QEMU approach:

  • Host OS: Requires Ubuntu Server 24.04 LTS or Debian 12 installation
  • Virtualization Stack: Uses KVM/QEMU with libvirt for VM management
  • Management: Primarily CLI-based using virsh commands (less user-friendly than Proxmox web UI)
  • Networking: Requires manual bridge configuration for direct LAN access
  • Resource Overhead: Similar to Proxmox (~2GB for host OS, 6-8GB for Start9 VM)
  • Pros: More familiar for existing Ubuntu/Debian users; native Linux tools
  • Cons: No built-in web UI; requires more manual configuration; less optimized for virtualization

If you prefer this approach, refer to Ubuntu/Debian KVM documentation:

  • Ubuntu KVM Installation Guide
  • Debian KVM Guide

Ongoing Management -> For Proxmox (Option A)

Proxmox Ongoing Management (Future)

  • Snapshots: Use Proxmox snapshots to safely test configuration changes and revert if needed. Take one before upgrades; keep only a few; prune old ones.
  • Backups: Use Proxmox web UI or vzdump command for automated backups. Schedule periodic VM backups to external storage (USB/NAS).
  • Updates: Keep Proxmox and Start9 OS up to date via their UIs.
  • Monitoring: Watch CPU, RAM, and disk; adjust VM resources as needed.
  • Security: Review firewall rules and user permissions on the node.

🌐 Host Services: The Proxmox host can still run other services (firewall, DNS, backup scripts, etc.).

Storage Upgrade Path (Future)

When you’re ready to add redundancy or expand storage:

  • Start with two SSDs in btrfs RAID1 for redundancy and low overhead.
  • Use live storage migration (pvmove) when replacing/expanding disks; consult Proxmox docs.
  • At 3+ SSDs, consider ZFS (Z2) for stronger integrity; budget extra RAM.
