Securing the Start9 VM with Proxmox Firewall Rules

The Proxmox datacenter firewall you configured in the previous guide protects the hypervisor host itself. The Start9 VM needs its own separate VM-level firewall — one that controls exactly which traffic can reach the Bitcoin node and which outbound connections the VM is allowed to make.

Without these rules the Start9 VM sits on the same LAN bridge as the AI agents VM and any other future VM, fully reachable from all of them. Locking it down at the VM level means that even if another VM were compromised, it cannot reach your Bitcoin node, your Lightning wallet, or your Electrs index.

In this guide, you will:

  • Enable the Proxmox VM-level firewall for the Start9 VM
  • Apply an inbound DROP-default policy allowing SSH and web access from your MacBook, wallet connections, and Bitcoin P2P ports
  • Apply an outbound DROP-default policy restricting egress to Bitcoin peers, Tor, updates, and the Proxmox backup share
  • Verify isolation from the AI agents VM before proceeding to software setup

Pre-requisites

Preparation

  • Proxmox VE secured following Securing Proxmox Virtual Environment
  • Start9 OS VM running and accessible from your MacBook browser
  • Your MacBook’s static LAN IP (check with ipconfig getifaddr en0 in Terminal)
  • The AI agents VM LAN IP, if already provisioned (assigned during Provisioning the AI VM)

Hardware

  • Minisforum X1-255 running Proxmox VE
  • Start9 VM running normally (you will verify isolation after applying rules)

Software

  • Proxmox VE web interface (Safari, Chrome, or Firefox)
  • SSH client (Terminal on macOS)

References

  • Proxmox VE Firewall Documentation

Step-by-Step Instructions

Step 1: Enable the VM-Level Firewall

  1. In the Proxmox web interface, select your Start9 VM from the left sidebar

  2. Click the Firewall tab → Options

  3. Double-click Firewall → set to Yes

  4. Set default policies:

    • Double-click Input policy → set to DROP
    • Double-click Output policy → set to ACCEPT (temporarily — you will restrict this in Step 3)

🛡️ Two-layer firewall: The Proxmox datacenter firewall protects the Proxmox host (ports 8006 and 22). These VM-level rules are separate — they protect the Start9 VM’s network boundary. Both layers must be active and each operates independently.

Step 2: Add Inbound Rules

Click the Firewall tab → Add to create each rule below in order.

🔑 Enable SSH inside Start9 first: The firewall rule opens the network path, but Start9 OS does not run SSH by default. Before testing SSH, go to the Start9 web interface → System → Manage → SSH → + Add New Key and paste your MacBook’s public key (pbcopy < ~/.ssh/id_ed25519.pub). Both steps are required.

Rule 1 — SSH from MacBook:
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: 192.168.1.XXX   ← your MacBook's static LAN IP
- Dest. port: 22
- Comment: SSH access from MacBook

Rule 2 — Start9 web UI (HTTPS) from MacBook:
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: 192.168.1.XXX   ← your MacBook's static LAN IP
- Dest. port: 443
- Comment: Start9 web UI + all service UIs (Mempool, BTCPay, Nostr, Vaultwarden, etc.)

Rule 3 — Start9 web UI (HTTP redirect) from MacBook:
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: 192.168.1.XXX
- Dest. port: 80
- Comment: HTTP → HTTPS redirect for Start9 UI

Rule 4 — Electrs Electrum protocol from MacBook:
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: 192.168.1.XXX
- Dest. port: 50001
- Comment: Sparrow / Electrum wallet connections (unencrypted Electrum protocol)

Rule 5 — Electrs TLS from MacBook:
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: 192.168.1.XXX
- Dest. port: 50002
- Comment: Sparrow / Electrum wallet connections (TLS)

Rule 6 — Bitcoin Core P2P (inbound peers):
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: (leave blank — any)
- Dest. port: 8333
- Comment: Bitcoin Core inbound peer connections — only reachable after router port forwarding is configured

Rule 7 — Lightning Network P2P (inbound channels):
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: tcp
- Source: (leave blank — any)
- Dest. port: 9735
- Comment: Lightning P2P inbound channels — only reachable after router port forwarding is configured

Rule 8 — mDNS (local hostname resolution):
- Enable: ☑
- Direction: in
- Action: ACCEPT
- Protocol: udp
- Source: (leave blank)
- Dest. port: 5353
- Comment: mDNS — MacBook resolves xxx-yyy.local hostnames for service UIs

  1. Verify the Start9 web interface is still reachable from your MacBook after enabling the firewall:

    • Open your browser and load https://192.168.1.XXX (Start9’s LAN IP)
    • The Start9 login page must load — if it does not, temporarily disable the VM firewall in Options → Firewall → No, fix the Source IP in Rule 2, and re-enable

🌐 Port 443 covers the Start9 admin panel. The Start9 management interface — and services that tunnel entirely through Start9’s HTTPS reverse proxy — are served at port 443, covered by Rule 2. However, some marketplace services (including Mempool Explorer) also expose their own web UI on a separate LAN port. If clicking “Launch UI” for a service opens a URL on a port other than 443, you need an additional inbound rule for that port from your MacBook’s IP. See the Troubleshooting section for details.

Tor .onion addresses for each service are handled entirely inside Start9’s Tor process, which connects to the Tor network through standard HTTPS ports. No inbound firewall rules are needed for Tor hidden services.

🛑 Bitcoin Core RPC port 8332 is intentionally absent from inbound rules. It is consumed only by other Start9 services internally (Electrs, Mempool, BTCPay). Exposing it on the LAN would allow any device to issue arbitrary RPC commands to your node.

📡 Rules 6 and 7 (ports 8333, 9735) have no effect yet. They only become reachable from the internet after you configure port forwarding on the AT&T BGW320 router pointing those ports at the Start9 VM’s LAN IP. Adding the rules now means the VM firewall is ready when you reach that step — you will not need to return here.

Step 3: Switch to Outbound DROP and Add Egress Rules

Now restrict outbound traffic so the Start9 VM can only reach what it legitimately needs.

  1. In Firewall → Options, double-click Output policy → set to DROP

  2. Click Add and create each outbound rule below:

Rule 9 — Block all traffic to AI VM (explicit isolation):
- Enable: ☑
- Direction: out
- Action: DROP
- Protocol: tcp
- Destination: 192.168.1.YYY   ← AI agents VM LAN IP
- Dest. port: (leave blank — all ports)
- Comment: Prevent Start9 from reaching AI VM

Rule 10 — DNS:
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: udp
- Dest. port: 53
- Comment: DNS resolution

Rule 11 — mDNS (local hostname advertisement):
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: udp
- Dest. port: 5353
- Comment: mDNS — Start9 advertises its xxx-yyy.local hostname on the LAN

Rule 12 — NTP (clock sync):
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: udp
- Dest. port: 123
- Comment: System clock sync

Rule 13 — Internet HTTP/HTTPS (updates, Tor, marketplace):
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: tcp
- Dest. port: 80,443
- Comment: Start9 marketplace, system updates, Tor bootstrap (Tor uses standard HTTPS ports)

Rule 14 — Bitcoin Core P2P outbound:
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: tcp
- Dest. port: 8333
- Comment: Bitcoin Core connecting to peers

Rule 15 — Lightning Network P2P outbound:
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: tcp
- Dest. port: 9735
- Comment: Lightning outbound channel and payment routing

Rule 16 — SMB backup to Proxmox host:
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: tcp
- Destination: 192.168.1.100   ← Proxmox host IP
- Dest. port: 445
- Comment: Start9 → Proxmox Samba share for encrypted backups

Rule 17 — Tor OR port (add only if Tor relay/bridge service is installed):
- Enable: ☑
- Direction: out
- Action: ACCEPT
- Protocol: tcp
- Dest. port: 9001
- Comment: Tor relay OR port — skip this rule unless you install the Start9 Tor Bridge or Relay service

🛡️ Rule ordering matters: Rule 9 (AI VM DROP) must appear above Rule 13 (broad ACCEPT for 80/443) in the rule list. Proxmox evaluates rules top-to-bottom and the first match wins, so the explicit DROP for the AI VM destination must fire before the broad port ACCEPT could match it. All other LAN devices are blocked by the output DROP default — no explicit DROP rules are needed for them.

🔒 Proxmox host access is locked down too: Rule 16 allows only port 445 (SMB) to the Proxmox host (192.168.1.100). All other ports to the Proxmox management interface — including port 8006 (web UI) — are blocked by the output DROP default. The Start9 VM has no legitimate reason to initiate connections to the Proxmox management interface.

Step 4: Verify Isolation

SSH into the Start9 VM (or open Start9’s web console) and run these checks:

# Confirm Start9 cannot reach the AI VM — should time out
curl --connect-timeout 5 http://192.168.1.YYY:11434
# Expected: curl: (28) Connection timed out

# Confirm internet access still works (required for blockchain sync and marketplace)
curl -s https://bitcoin.org | head -5
# Expected: HTML content returned

# Confirm backup path to Proxmox host is open
timeout 5 bash -c 'echo >/dev/tcp/192.168.1.100/445' 2>/dev/null && echo "Port open" || echo "Port blocked"
# Expected: Port open

From your MacBook, confirm .local hostname resolution works (required for service UIs):

ping -c 3 xxx-yyy.local
# Expected: replies from 192.168.1.101

Troubleshooting

Cannot SSH to the Start9 VM (connection timed out):

  • The firewall is dropping port 22. Verify Rule 1 is enabled (☑), Source IP matches your MacBook, and Dest. port is 22. Also confirm SSH is enabled inside Start9 OS: System → Manage → SSH — if no key is listed, add your public key there before retrying.

Start9 web interface unreachable after enabling VM firewall:

  • Verify Rule 2 is enabled (☑), the Source IP exactly matches your MacBook’s LAN IP, and port is 443. Temporarily disable the firewall in Options → Firewall → No, fix the Source IP, re-enable.

Bitcoin Core shows 0 inbound peers:

  • This is expected without router port forwarding. Start9 connects to peers outbound via Rule 14. Inbound peers via Rule 6 only apply after you configure the AT&T BGW320 to forward port 8333 to the Start9 VM’s LAN IP.

Start9 backup to Proxmox Samba share fails after adding outbound DROP:

  • Verify Rule 16 is enabled and Destination is exactly 192.168.1.100. Test from the Start9 VM: timeout 5 bash -c 'echo >/dev/tcp/192.168.1.100/445' 2>/dev/null && echo "Port open" || echo "Port blocked" — should print Port open. If it prints Port blocked, check Rule 16’s destination and port.

Sparrow or Electrum wallet cannot connect to Electrs:

  • Verify Rules 4 and 5 are enabled with the correct Source IP (your MacBook’s LAN IP). Confirm Electrs is running and fully indexed in the Start9 web UI before testing wallet connections.

Service “Launch UI” opens https://xxx-yyy.local but the page does not load (ping xxx-yyy.local fails):

  • Start9 may not be running avahi-daemon, so it never broadcasts its .local hostname via mDNS. The reliable fix is a static hosts entry on your MacBook — add it once and it persists across reboots:

    echo "192.168.1.101 xxx-yyy.local" | sudo tee -a /etc/hosts

    Replace xxx-yyy.local with your actual Start9 hostname. macOS checks /etc/hosts before mDNS for .local names. After adding the entry, ping xxx-yyy.local should resolve to 192.168.1.101 and all service UIs will load.

  • If ping resolves but the browser still shows a certificate error, install the Start9 Root CA in your MacBook’s Keychain — see Securing Start9 OS — Step 3.

A service’s “Launch UI” button opens a blank or timed-out page:

  • The service web UI is served on a port that is not in the inbound rules. Look at the URL in the failed browser tab — it will show the port number (e.g., http://192.168.1.101:4080). Add an inbound rule for that port with your MacBook’s LAN IP as the source. See Installing Mempool Explorer — Troubleshooting for a worked example.
  • The Start9 admin panel (port 443) and individual service web UIs can run on different ports. Rule 2 covers the admin panel and proxied services, but not services that expose a dedicated LAN port.
