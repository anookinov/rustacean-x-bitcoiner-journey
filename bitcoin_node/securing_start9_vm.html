Securing Start9 OS and VM Environment

This guide provides step-by-step instructions to secure your Start9 OS instance—whether running natively or as a Proxmox VM—before installing Bitcoin Core and other self-sovereignty software. Securing your operating system is essential for protecting your node, wallets, and all self-hosted services from unauthorized access, data loss, and privacy threats.

Objectives:

  • Change the Start9 master password to a strong, unique value
  • Configure and verify automatic encrypted backups
  • Enable Tor for anonymous, private access to your node
  • Verify system health, resources, and connectivity
  • Document your configuration and backup details securely

Pre-requisites

Before starting, ensure you have completed the initial Start9 OS setup and have access to the web interface from a trusted device.

Preparation

  • Start9 OS installed and booted (native or as a Proxmox VM)
  • Initial Start9 setup wizard completed
  • Master password set during initial setup
  • Access to Start9 web interface (https://xxx-yyy.local or via IP address)

Hardware

  • Start9 OS device (native hardware or Proxmox VM)
  • MacBook, desktop, or laptop for secure access and documentation
  • USB drive, NAS, or external storage for backups (optional)

Software

  • Start9 OS running (latest stable release)
  • Web browser (Safari, Chrome, Firefox, etc.)
  • SSH client for advanced access (optional)
  • or Browser for private access (optional)

Step-by-Step Instructions

Step 1: Change Start9 Master Password

The master password is your primary access control to Start9. Set a strong, unique password:

  1. Access Start9 web interface: https://xxx-yyy.local or https://192.168.1.101
  2. Log in with your existing master password
  3. Click on System in the sidebar
  4. Go to Manage
  5. Select Change Master Password
  6. Enter your current password
  7. Enter new strong password (20+ characters)
  8. Confirm new password
  9. Click Change Password

🔒 Password Recommendations:

  • Minimum 20 characters
  • Mix uppercase, lowercase, numbers, special characters
  • Use passphrase format (e.g., Bitcoin*Sovereignty2025!)
  • Store securely in password manager
  • Keep backup written down in secure location

Step 2: Configure Start9 Backup & Recovery

Back up your Start9 OS before proceeding. First, decide where you want to store your backup. Start9 supports several backup destinations:

Backup destination options (for this setup):

  • Internal SSD (chosen): A dedicated folder on the 1TB SSD used by Proxmox VE and other VMs, selected because it has ample available space for regular backups. This SSD is separate from the 2TB SSD fully allocated to Start9 OS and its data, ensuring true redundancy and protecting against data loss if the main Start9 disk fails.
  • Local storage: USB drive connected to Start9 (optional, for portability and offline safety)
  • External storage: NAS or external hard drive on your local network (optional)
  • Cloud backup: Encrypted backup to a supported cloud provider (optional)

🔐 Backup Safety: Backups contain all your service data, private keys, and configurations. Store them securely and encrypt if using external storage.

If you choose to use an internal SSD (allocated to Proxmox VE and other services/VMs) as your backup destination, follow these steps:

How to prepare and use an internal SSD for Start9 backups:

  1. On your Proxmox VE host, identify the 1TB SSD (used for Proxmox VE and other VMs) that has available space for backups. Do not use the 2TB SSD fully allocated to Start9 OS and its data—this is for redundancy.

    To create a dedicated backup folder on the 1TB SSD:

    • Log in to your Proxmox VE host via SSH or the web shell.

    • Create a folder for Start9 backups (e.g., /mnt/start9-backups):

      sudo mkdir -p /mnt/start9-backups
# Check the UID and GID for the 'start9' user and group:
id start9
# Example output: uid=1000(start9) gid=1001(start9) ...
# Use these values to set ownership:
sudo chown 1000:1001 /mnt/start9-backups
# (Replace 1000:1001 with the actual UID:GID if different)

🧑‍💻 Create start9 User and Group (if needed):

sudo groupadd -g 1001 start9
sudo useradd -m -u 1000 -g 1001 start9
sudo passwd start9

This creates a start9 user with UID 1000 and GID 1001, and sets a password for use as backup credentials.

  • (Optional) If you want to use a dedicated partition, use lsblk to identify free space, then partition and format it (e.g., with fdisk and mkfs.ext4), then mount it at /mnt/start9-backups and add to /etc/fstab for persistence.

  • Next, map the directory in Proxmox VE:

  • In the Proxmox web UI, go to Datacenter → Directory Mapping.

  • Click Add.

  • In the pop-up, fill in the following attributes:

    • Name: start9-backups
    • Path: /mnt/start9-backups
    • Node: (select your Proxmox node)
    • Comment: (optional, e.g., “Start9 backup storage”)

  • Click Create to add the mapping.

  1. Make this folder accessible to your Start9 VM as a network share (SMB/CIFS or NFS):

    Set up an SMB (Samba) or NFS share for /mnt/start9-backups on your Proxmox host, and connect to it from the Start9 OS using the backup destination setup. Ensure network access and permissions are configured appropriately.

    → For detailed instructions, see How to Set Up an SMB (Samba) or NFS Share on Proxmox VE

  2. In the Start9 web interface, click on System in the sidebar.

  3. Go to Backups.

  4. Click Create Backup.

  5. In the backup dialog, click Open New to select or add a new backup destination.

  1. Fill in values for backup destination attributes to create new network folder:

    • Hostname/IP: The IP address or hostname of your Proxmox host (e.g., 192.168.1.100)
    • Path: The shared folder path (e.g., /mnt/start9-backups)
    • Username: The user account with access to the share (e.g., start9 or your Proxmox user)
    • Password: The password for the above user account

  2. After filling in the backup destination values, click the Connect button to continue.

  3. Select the Start9 services you want to back up (e.g., Bitcoin Core, Electrs, Mempool) by checking their boxes.

  1. Click Back Up Selected button to continue.
  2. When prompted, enter your Start9 master password (this will be used to encrypt the backup).
  3. Click Create Backup button to start the process.
  4. Wait for the backup to complete and verify that it finishes successfully.
  • You can verify backup completion in two ways:
    • Via notification:
      • Under Notifications, a notification will appear when the backup completes successfully.
    • Via last backup info:
      • The last backup information is shown under System → Backups → Create Backup menu.

💡 Backup Tip:

Start9 backups cannot be scheduled automatically. Make it a habit to perform manual backups regularly—especially after major changes, updates, or installing new services. This ensures your data and configurations are always protected.

Step 3: Enable Tor Service for Anonymity

Start9 OS includes built-in Tor support for accessing your node privately.

  1. In the Start9 web interface, click on System in the sidebar.
  2. Go to About.
  3. Under Web Addresses, locate the Tor address (looks like: abcd1234efgh5678.onion).
  4. Document your Tor address securely.

Benefits:

  • Access Start9 from anywhere without exposing your IP
  • Enhanced privacy when connecting to your node
  • Protection from ISP monitoring

Usage:

  • Install Tor Browser on your MacBook
  • Navigate to your .onion address to access Start9 securely
  • Connect wallets and services via Tor for maximum privacy

How to install Tor Browser on macOS:

📱 iOS Access Guide: See Accessing Start9 Web Interface via Tor on iOS for step-by-step instructions.

  1. Go to Tor Browser Download Page — Official site to download the Tor Browser for macOS, Windows, and Linux.

  2. Click Download for macOS

  3. Verify the download (critical security step):

    • On the Tor Project page, find the “Signature” link next to your macOS download
    • Download both the .dmg file and its .asc signature file
    • Open Terminal and run:
    # Install GnuPG if needed
brew install gnupg

# Navigate to Downloads folder
cd ~/Downloads

# Verify the signature
# Optional: Fetch the key (may fail if keyserver is down)
gpg --recv-keys 0xEBE9E286975A05796955E2084E3EDDDD37601E14 2>/dev/null || true

# Verify - this works even if recv-keys fails (uses cached key or key in signature)
gpg --verify tor-browser-macos-15.0.3.dmg.asc tor-browser-macos-15.0.3.dmg
    • You should see: “Good signature from Tor Project” ✓
    • If you see “no public key” error, try the recv-keys command again or download the key manually from https://keys.openpgp.org/
    • If signature verification fails, do not use the file - download again

  4. Open the verified .dmg file

  5. Drag Tor Browser to your Applications folder

  6. Open Applications → Tor Browser

  7. Click Connect to connect to the Tor network (takes 30-60 seconds)

  8. Once connected, paste your Start9 .onion address in the address bar

  9. You may see a certificate warning - This is normal and expected

About the HTTPS certificate warning:

When you access your Start9 .onion address via Tor Browser, you’ll likely see:

Warning: Potential Security Risk Ahead
Tor Browser detected a potential security threat...

This is NOT a security problem. Here’s why:

  • Start9 uses a self-signed certificate (not from a Certificate Authority)
  • Self-signed certs are normal for local/private services
  • Tor Browser warns about self-signed certs as a precaution
  • Your connection is still encrypted via Tor

How to proceed:

  1. Click Advanced → Accept the Risk and Continue
  2. You’ll now see Start9 login page
  3. Log in with your Start9 master password
  4. The connection is secure (traffic goes through Tor encryption + HTTPS)

Why self-signed certs are fine here:

  • You’re connecting to your own hardware via Tor (private network)
  • Tor provides encryption and anonymity
  • Certificate validation is less critical for personal services
  • This is standard practice for self-hosted services

How to permanently fix the certificate warning:

There are two approaches:

Option 1: Install a valid certificate (Advanced)

🛡️ macOS Security Prompt: During this process, macOS will prompt you to enter your Mac password to confirm changes to the System keychain and trust settings.

  1. In the Start9 web interface, click on System in the sidebar.
  2. Go to Manage.
  3. Click the Root CA section.
  4. Click the Download Root CA button to download the certificate authority file.
  5. Install the Root CA on your Mac to trust your Start9’s self-signed certificates:
    • Double-click the downloaded Root CA file (named after your Start9 device, e.g., xxx-yyy.crt).
    • The Keychain Access app will open. Choose System as the keychain and click Add.
    • In Keychain Access, find the imported certificate under the System keychain, named after your Start9 device (e.g., xxx-yyy Local Root CA).
    • Double-click the certificate, expand Trust, and set When using this certificate to Always Trust.
    • Close the window.
    • Restart your browser (including Tor Browser) for the changes to take effect.
    • Your browser will now trust your Start9’s self-signed certificates, and you should no longer see HTTPS warnings when accessing your node.
  6. Once installed, your browser (including Tor Browser) will recognize the certificate as valid for your Start9 services.

Option 2: Trust the self-signed certificate (Simple)

  1. On first visit, click Advanced → Accept the Risk and Continue
  2. Tor Browser will remember the certificate for this .onion address
  3. On future visits, the warning may not appear (or appear less prominently)
  4. This is the practical approach for personal self-hosted services

Option 3: Use HTTP (Least Secure)

  1. Access Start9 over unencrypted HTTP (not recommended)
  2. Less security but no certificate warnings
  3. Not recommended - defeats the purpose of HTTPS

Recommendation:

  • For personal use: Option 2 (accept and continue) is recommended and widely used
  • For multiple users or shared environments: Option 1 (install Root CA) is more secure and preferred
  • Most Bitcoin node operators use Option 2 without issues; Option 1 is for advanced or multi-user setups

Why verify the signature?

  • Protects against man-in-the-middle attacks
  • Ensures the file hasn’t been tampered with
  • Verifies it’s authentic Tor Project software

🕸️ Tor Connection Tip: The first connection may take a few seconds as Tor establishes a circuit. If you see a security warning, ensure you typed the .onion address correctly.

Alternative: Using curl with Tor (command line):

# If you prefer CLI access:
brew install tor

# If you get an error on MacBook Air M1 (Apple Silicon):
arch -arm64 brew install tor

# Start Tor daemon
tor &

# Access your Start9 .onion address via Tor proxy
curl -x socks5h://127.0.0.1:9050 https://abcd1234efgh5678.onion

💡 Note for Apple Silicon (M1/M2/M3) Macs: If you see errors with brew install tor, use arch -arm64 brew install tor to ensure Tor is installed for your Mac’s ARM64 architecture. This avoids compatibility issues and ensures Tor runs natively and efficiently.

Step 4: SSH Access (Optional)

🛡️ SSH Security Note: SSH access to Start9 is not critical for running a Bitcoin node. The web interface provides everything you need. Skip this unless you specifically need command-line access.

If you want command-line access to Start9:

  1. In the Start9 web interface, click on System in the sidebar.

  2. Go to Manage.

  3. Click on SSH.

  4. Click the + Add New Key button to add your SSH public key.

  5. Paste your SSH public key and save:

    • If you do not have an SSH key, generate one on your MacBook by running:

      ssh-keygen -t ed25519 -C "your_email@example.com"
# or use rsa if needed:
# ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

    • By default, your public key will be in ~/.ssh/id_ed25519.pub (or id_rsa.pub).

    • To copy your public key to the clipboard, run:

      pbcopy < ~/.ssh/id_ed25519.pub
# or for RSA:
# pbcopy < ~/.ssh/id_rsa.pub

    • In the Start9 web interface, paste the copied key into the field provided and click Submit.

  6. From your MacBook, connect using:

    ssh start9@192.168.1.101

🛑 Troubleshooting: SSH Host Key Has Changed

If you see a warning like:

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
IT IS POSSIBLE THAT SOMEONE IS DOING SOMETHING NASTY!
Someone could be eavesdropping on you right now (man-in-the-middle attack)!
It is also possible that a host key has just been changed.
Host key verification failed.

This usually happens after reinstalling or resetting your Start9 device. To fix:

  1. If you trust the new key, remove the old key from your known_hosts file:

    ssh-keygen -R 192.168.1.101

  2. Try connecting again:

    ssh start9@192.168.1.101

    Accept the new host key when prompted.

Step 5: Network Configuration

🗄️ Proxmox VM Only: This step is only for Proxmox VM users. Skip if running native Start9.

If running Start9 as a Proxmox VM, verify the VM network:

  1. In Proxmox web interface, select your Start9 VM

  2. Go to Hardware → Network Device

  3. Verify:

    • Bridge: vmbr0 (or your bridge name)
    • Model: VirtIO (fastest)
    • MAC Address: Should be assigned by DHC

Step 6: Verify Internet Connectivity (Final Check)

🌐 Network Requirement: This step is informational only. Start9 needs internet access to sync the Bitcoin blockchain and reach peers.

Before installing Bitcoin Core, verify:

  1. Test from MacBook:

    # Ping Start9 IP
ping 192.168.1.101

# Or by hostname if using mDNS
ping xxx-yyy.local

  2. Check Start9 web interface: Load https://192.168.1.101 - if it loads, internet works

If connectivity fails:

  • Check Proxmox VM network settings
  • Verify DHCP lease on router
  • Restart the VM
  • Check cable connections (if native hardware)

Accessing Start9 Web Interface via Tor on iOS

You can securely access your Start9 web interface from your iPhone or iPad using the Tor Browser app. This is useful for remote administration or when you want to use your .onion address for privacy.

  1. Install Tor Browser

    • Download the recommended Tor browser app for iOS: Onion Browser by Mike Tigas, available for free on the iOS App Store. This is the most widely used and trusted Tor browser for iPhone and iPad, endorsed by the Tor Project.
    • In the App Store, search for “Onion Browser” (developer: Mike Tigas) and verify it is the official app. Avoid unofficial clones or apps with few reviews.
    • Open Onion Browser and complete any initial setup prompts.

  2. Get Your Start9 .onion Address

    • In the Start9 web interface (from a trusted device), go to System → About.
    • Under Web Addresses, copy your Tor’s .onion address (e.g., abcdefg123456789.onion).

  3. Open the .onion Address in Tor Browser

    • Open the Tor Browser app on your iOS device.
    • Paste your Start9 .onion address into the address bar and press Go.
    • Log in with your Start9 credentials as usual.

📱 Tor Mobile Tips:

  • For best security, always use the Tor Browser app for .onion addresses.
  • You can bookmark your Start9 .onion address in the app for quick access.
  • If you have trouble connecting, check that Tor is enabled on your Start9 device and your mobile device has internet access.

How to Set Up an SMB (Samba) or NFS Share on Proxmox VE

SMB (Samba) vs NFS: Pros and Cons

FeatureSMB (Samba)NFS
CompatibilityWorks on Windows, macOS, LinuxBest for Linux/Unix, limited Windows support
PerformanceSlightly slower on Linux, good on WindowsGenerally faster on Linux
AuthenticationUser/password, supports granular permissionsHost-based, simpler but less granular
Ease of SetupMore config steps, more optionsSimpler for Linux hosts and clients
SecuritySupports encryption, user authNo built-in encryption, relies on network
Use CaseMixed-OS networks, Windows/macOS clientsLinux-to-Linux sharing, VM environments
Firewall Ports445, 139 (SMB/CIFS)2049 (NFS)
StabilityVery stable, mature protocolVery stable, mature protocol

Summary:

  • Use SMB (Samba) if you need compatibility with Windows or macOS, or want user-based access control.
  • Use NFS for Linux-only environments or when you want simpler, faster file sharing between Linux systems (like Proxmox and Linux VMs).

To set up an SMB (Samba) share (used in this guide)

  1. Check that the start9 user and group exist and have the correct UID and GID:

    id start9
getent group 1001

  2. Check the ownership of the backup directory:

    ls -ld /mnt/start9-backups

  3. Install Samba if not already installed:

    sudo apt update
sudo apt install samba

  4. Edit the Samba configuration file:

    sudo nano /etc/samba/smb.conf

  5. Add a section for your backup share at the end of the file:

    [start9-backups]
path = /mnt/start9-backups
browseable = yes
read only = no
guest ok = no
valid users = start9
force user = start9
force group = start9
create mask = 0660
directory mask = 0770

  6. Set a Samba password for the start9 user:

    sudo smbpasswd -a start9

  7. Restart Samba:

    sudo systemctl restart smbd

  8. Ensure your firewall allows SMB/CIFS (port 445; port 139 is only needed for legacy systems).

🛡️ Firewall Troubleshooting:

If you have trouble connecting to your Samba share, the issue is usually with the firewall on your Proxmox Datacenter or the Start9 VM itself—not your AT&T or home router. By default, most home routers allow local LAN traffic, so no changes are needed there.

Where to check:

  • Proxmox Datacenter: Check the firewall settings in the Proxmox web UI under Datacenter → Firewall and on the specific node or VM. Enable TCP port 445 (both IN and OUT) for SMB/CIFS.
  • Proxmox PVE Node: Also check the firewall settings for the Proxmox PVE node itself (Node → Firewall) to ensure TCP port 445 is allowed for SMB/CIFS traffic between the node and VMs.
  • Start9 VM: If the firewall is enabled for the Start9 VM via the Proxmox web UI (VM → Firewall), ensure it allows inbound SMB/CIFS traffic on TCP port 445.
  • Client device: If your Mac, Linux, or Windows client has a firewall, ensure it allows outbound connections to these ports.

Testing connectivity:

  • On Linux/macOS: nc -zv <proxmox-ip> 445
  • On Windows: telnet <proxmox-ip> 445
  • Successful connection means port 445 is open and reachable.

For most home networks, no router changes are required. Only adjust router settings if you have custom LAN firewall rules. Never open SMB/CIFS ports to the internet for security reasons.

To set up an NFS share

NFS shares are not used or covered in this mdbook. If you require an NFS share for your environment, please refer to the official Proxmox or Linux documentation for up-to-date instructions:

  • Proxmox: How to add an NFS share
  • Ubuntu: NFS server setup

NFS is generally recommended only for advanced Linux-to-Linux sharing scenarios. For most users, SMB (Samba) is preferred for compatibility and ease of use.
