Securing Proxmox Virtual Environment (VE)

This guide provides step-by-step instructions to secure your Proxmox VE host before running Start9 OS or Bitcoin node VMs. Securing the hypervisor is essential to protect your Bitcoin infrastructure and all hosted services from unauthorized access and network threats.

In this guide, you will:

  • Harden Proxmox VE authentication and access controls
  • Configure firewall and network security
  • Set up user management and SSH best practices
  • Review maintenance and advanced security options

Pre-requisites

Preparation

  • Access to your Proxmox VE host (IP address, credentials)
  • Ability to SSH into the Proxmox server from your MacBook or workstation
  • Familiarity with basic Linux commands

Hardware

  • Proxmox VE host machine (physical or virtualized)
  • Reliable network connection between your MacBook and Proxmox host

Software

  • Proxmox VE installed and accessible via web interface (e.g., https://192.168.1.100:8006)
  • SSH client (Terminal app on macOS)
  • Password manager for storing credentials securely

References

  • Proxmox Official Documentation
  • Proxmox Firewall Documentation
  • Proxmox User Management
  • Linux SSH Security Best Practices

Step-by-Step Instructions

Step 1: Update Proxmox VE

Before making configuration changes, update the Proxmox host to the latest security patches.

  1. SSH into the Proxmox host:

    ssh root@192.168.1.100

  2. Update package lists and upgrade:

    apt update && apt dist-upgrade -y

  3. Reboot if the kernel or critical packages were upgraded:

    reboot

📦 Repository Guidance: If you use the Proxmox enterprise repository, ensure your subscription is valid. Non‑enterprise users can enable the no‑subscription repo following Proxmox guidance.

Step 2: Change Proxmox Root Password

The default root password is set during installation. Change it immediately to a strong, unique password.

  1. Access Proxmox web interface: https://192.168.1.100:8006
  2. Log in as root with your initial password
  3. Click on Datacenter → Permissions → Users (or top-right profile menu)
  4. Find root@pam in the user list
  5. Click the Password button for the root user
  6. In the pop-up, enter and confirm a strong, unique password (20+ characters, mix of case/numbers/symbols)
  7. Click OK to save

🔑 Password Recommendations:

  • Minimum 20 characters
  • Mix uppercase, lowercase, numbers, special characters
  • Use passphrase format (e.g., CorrectHorseBatteryStaple!2025)
  • Store securely in password manager

Step 3: Configure SSH Key-Based Authentication

Set up SSH keys for secure, password-less access to Proxmox:

  1. Check for Existing SSH Key

    First, check if you already have an SSH key pair on your MacBook:

    ls -la ~/.ssh/

    If you see an Ed25519 key pair, you can reuse it and proceed directly to next step to copy your existing public key to Proxmox:

    • id_ed25519 (private key)
    • id_ed25519.pub (public key)

    If you don’t see an Ed25519 key pair, generate a new one:

    ssh-keygen -t ed25519 -C "proxmox@192.168.1.100" -f ~/.ssh/id_proxmox
    • When prompted for passphrase, enter a strong password (or leave blank for no passphrase)
    • File will be saved to ~/.ssh/id_proxmox
    • Verify the key was created:
    ls -la ~/.ssh/id_proxmox*
# Should show: id_proxmox (private key) and id_proxmox.pub (public key)

  2. Copy SSH Public Key to Proxmox Root

    • Determine which public key to use:

      • If using existing Ed25519 key: ~/.ssh/id_ed25519.pub
      • If using new key: ~/.ssh/id_proxmox.pub

    • SSH to Proxmox with password (one last time):

    ssh root@192.168.1.100
    • Create SSH directory if it doesn’t exist:
    mkdir -p /root/.ssh
chmod 700 /root/.ssh
    • On your MacBook (in a new terminal), copy your public key:
    # If using existing id_ed25519.pub:
cat ~/.ssh/id_ed25519.pub | ssh root@192.168.1.100 "cat >> /root/.ssh/authorized_keys"

# OR if using new id_proxmox.pub:
cat ~/.ssh/id_proxmox.pub | ssh root@192.168.1.100 "cat >> /root/.ssh/authorized_keys"
    • Set correct permissions on Proxmox:
    ssh root@192.168.1.100
chmod 600 /root/.ssh/authorized_keys
    • Verify the key was added:
    ssh root@192.168.1.100
cat /root/.ssh/authorized_keys
# Should show your public key starting with "ssh-ed25519"

  3. Test SSH Key Access

    From your MacBook, test SSH with the key:

    # If using existing id_ed25519:
ssh root@192.168.1.100
# SSH should automatically use ~/.ssh/id_ed25519

# OR if using id_proxmox:
ssh -i ~/.ssh/id_proxmox root@192.168.1.100

    Should log in without asking for password (unless you set a passphrase on the key).

    If prompted for a passphrase (not password), enter the passphrase you set when creating the key.

🔐 SSH Agent Tip: Add the key to SSH agent to avoid entering passphrase repeatedly.

# If using id_ed25519:
ssh-add ~/.ssh/id_ed25519

# OR if using id_proxmox:
ssh-add ~/.ssh/id_proxmox

# Now SSH will use the cached key without asking for passphrase

Step 4: Disable SSH Root Login

After confirming SSH key access works, disable password authentication:

  1. SSH into Proxmox host:

    # If using existing id_ed25519 (it auto-connects):
ssh root@192.168.1.100

# OR if using id_proxmox:
ssh -i ~/.ssh/id_proxmox root@192.168.1.100

  2. Edit SSH configuration:

    nano /etc/ssh/sshd_config

  3. Find and modify these lines:

    PermitRootLogin prohibit-password
PasswordAuthentication no
PubkeyAuthentication yes

    Explanation:

    • PermitRootLogin prohibit-password: Allow root login only with SSH keys, not passwords
    • PasswordAuthentication no: Disable password-based authentication entirely
    • PubkeyAuthentication yes: Enable SSH key authentication

  4. Save the file (Ctrl+O, Enter, Ctrl+X)

  5. Restart SSH service:

    systemctl restart ssh

  6. Important: Keep your current SSH session open and test from a new terminal:

    # Test with explicit key path (works even if path is wrong - SSH tries default keys):
ssh -i ~/.ssh/id_proxmox root@192.168.1.100
# Should work

# Test with SSH agent (auto-uses available keys):
ssh root@192.168.1.100
# Should work (uses default key or SSH agent)

# Test that password auth is disabled:
ssh -o PubkeyAuthentication=no root@192.168.1.100
# Should fail (no password prompt, connection refused)

🔑 SSH Key Path Tip: SSH is forgiving with key paths - if you specify -i ~/.ssh/ed25519 but the key doesn’t exist there, SSH will automatically try default key locations like ~/.ssh/id_ed25519 or keys in your SSH agent. This is why both -i ~/.ssh/ed25519 and -i ~/.ssh/id_ed25519 work!

Security Benefits:

  • No brute-force password attacks possible
  • SSH key is stored locally on your MacBook
  • Only devices with the private key can access Proxmox

Step 5: Configure Proxmox Firewall

Enable the host firewall to restrict traffic:

  1. In Proxmox web interface, go to Datacenter → Firewall
  2. Enable IN policy: Set to DROP (deny all inbound by default)
  3. Enable OUT policy: Set to ACCEPT (allow all outbound)
  4. Click Save

Step 6: Add Firewall Rules for Management Access

Allow only necessary ports:

Management Access:

  • Port 8006 (HTTPS web interface) - from your home network

Important: Proxmox firewall rules are organized in Security Groups. You must create a Security Group first, then add rules to it.

  1. Create a Security Group

    • Go to Datacenter → Firewall → Security Group
    • Click Create button
    • Enter the following:
      • Name: Management-Access (or similar name)
      • Comment: Allow management traffic for Proxmox host (optional but recommended)
    • Click Create

  1. Add Firewall Rules to Security Group

    • With your new Security Group selected, click Add Rule
    • Create the following ACCEPT rules (in order):

Important: Add rules in this order and test each before proceeding!

Rule 1 - Proxmox Web Interface:
- Enable: ☑ (checked)
- Direction: In
- Action: ACCEPT
- Protocol: tcp
- Dest Port: 8006
- Source: 192.168.1.0/24 (your home network)
- Macro: (leave blank)
- Comment: "Proxmox web interface (Datacenter)"

Rule 2 - SSH Access:
- Enable: ☑ (checked)
- Direction: In
- Action: ACCEPT
- Protocol: tcp
- Dest Port: 22
- Source: 192.168.1.0/24 (your home network)
- Macro: (leave blank)
- Comment: "SSH key-based access"

  1. Insert Security Group into Datacenter Firewall

    • Go to Datacenter → Firewall
    • Click the Insert: Security Group button
    • Select your created Security Group (e.g., Management-Access)
    • Click Add to add the group to the Datacenter firewall rules
  1. Test ACCEPT rules
    • After adding Rules 1 and 2 and inserting the Security Group, verify you can still access:
      • Proxmox web interface: https://192.168.1.100:8006
      • SSH: ssh root@192.168.1.100
    • If access works, you’re done! The DROP Input Policy handles the rest.
    • If access fails, troubleshoot ACCEPT rules (check Enable is ☑, verify port numbers, confirm Security Group is inserted)

About the default DENY behavior:

You don’t need to add a specific DENY rule because you already configured Input Policy = DROP in Step 4 (Datacenter → Firewall → Options). Here’s how this works:

  • DROP policy: By default, ALL inbound traffic is silently discarded (no response sent)
  • ACCEPT rules: Create exceptions to the DROP policy for ports 8006 and 22
  • Result: Only ports you explicitly ACCEPT are allowed; everything else is dropped

DROP vs REJECT:

  • DROP: Silently discards packets (no response to sender). Recommended for security - attackers don’t know if port exists.
  • REJECT: Sends ICMP error back to sender. Lets attackers know port exists but is blocked. Not recommended for external interfaces.

About Enable checkbox and Macro:

  • Enable: Must be checked (☑) for rule to be active
  • Macro: Provides predefined rule templates (e.g., “HTTP”, “HTTPS”, “SSH”). Leave blank for custom rules.

Order matters: Rules are evaluated top-to-bottom. ACCEPT rules match first, then DROP policy catches everything else.

Step 7: Enable the Firewall

🛡️ Firewall Activation Required: The firewall configuration doesn’t take effect until you enable it!

  1. Go to Datacenter → Firewall → Options
  2. Find Firewall setting (at the top of the options list)
  3. Double-click on the Firewall row to edit it
  4. Check the box to enable the firewall
  5. Click OK

What happens when you enable:

  • Your ACCEPT rules for ports 8006 and 22 will allow access
  • All other inbound traffic will be DROPped (silently discarded)
  • You should still be able to access web UI and SSH (if rules are correct)

Safety check after enabling:

  • Verify web interface still works: https://192.168.1.100:8006
  • Verify SSH still works: ssh root@192.168.1.100
  • If you lose access, use Proxmox console to disable firewall: pve-firewall stop

Step 8: Review User Accounts

Proxmox supports multiple user accounts. You can manage them for team collaboration:

🗝️ Solo Operator Advice: For solo Bitcoin node operators, the root account with SSH keys is all you need.

  1. Go to Datacenter → Permissions → Users (or Datacenter → User Management in older versions)
  2. Review all users in the list
  3. For Bitcoin node setups, the root account is sufficient
  4. Remove any default or test accounts if you want to minimize attack surface

👤 User Account Setup Tip: Recommended setup:

  • One admin account (root) with strong SSH key authentication
  • Use SSH key-based auth only (no password login)
  • Skip additional users unless you need team collaboration
