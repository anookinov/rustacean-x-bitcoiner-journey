Rustacean X Bitcoiner Journey

Remote Claude Code Access from iPhone via Tor

After building a full Bitcoin node stack, the natural next experiment is: can I manage my Claude Code AI agents on the MacBook from my iPhone, from anywhere, without opening any port to the internet or using any cloud service?

The answer is yes — using a hardened Tor hidden service on the MacBook. The MacBook exposes its SSH port as a .onion address through the Tor network, protected by Tor v3 client authorization and SSH public-key-only authentication. The iPhone connects via Orbot (iOS Tor proxy) and Termius (SSH client). No port forwarding, no VPN subscription, no cloud server.

Security model:

  • SSH is restricted to 127.0.0.1 — unreachable from the LAN or internet without Tor
  • Tor v3 client authorization means only your iPhone can reach the hidden service at all
  • Password authentication is completely disabled — only Ed25519 public key accepted
  • The .onion address itself is unknown to anyone who does not hold the client auth private key

In this guide, you will:

  • Install Tor on MacBook via Homebrew
  • Configure a Tor v3 hidden service for SSH
  • Generate a Tor v3 client authorization keypair (only your iPhone can connect to the .onion address)
  • Harden sshd_config to disable password auth and restrict SSH to localhost only
  • Generate an Ed25519 SSH key pair and install the public key
  • Enable SSH (Remote Login) on MacBook after hardening is in place
  • Install tmux on MacBook for persistent Claude Code sessions
  • Install VS Code and the Claude Code extension on MacBook
  • Install Orbot on iPhone and import the Tor client auth key
  • Install Termius on iPhone and connect using the Ed25519 key
  • Install ntfy on iPhone for push notifications from Claude Code
  • Configure Claude Code hooks to send real-time notifications to iPhone
  • Test the complete end-to-end workflow

Step-by-Step Instructions

Step 1: Install Tor on MacBook

  1. Open Terminal on your MacBook

  2. Install Tor via Homebrew:

    brew install tor

  3. Confirm the Homebrew prefix (differs between Intel and Apple Silicon):

    brew --prefix
    • Apple Silicon (M1/M2/M3/M4): /opt/homebrew
    • Intel Mac: /usr/local

    The steps below use $(brew --prefix) so they work on both architectures automatically.

Step 2: Configure Tor Hidden Service for SSH

  1. Create a permanent directory to store the hidden service keys, hostname, and client authorization:

    mkdir -p ~/.tor/ssh_hidden_service/authorized_clients
chmod 700 ~/.tor/ssh_hidden_service
chmod 700 ~/.tor/ssh_hidden_service/authorized_clients

  2. Confirm your macOS username:

    whoami

  3. Open the Tor configuration file (Homebrew does not create this file by default — nano will open a blank new file, which is expected):

    nano $(brew --prefix)/etc/tor/torrc

  4. The file will be blank. Type these lines (replace yourusername with your macOS username from the previous step):

    HiddenServiceDir /Users/yourusername/.tor/ssh_hidden_service
HiddenServiceVersion 3
HiddenServicePort 22 127.0.0.1:22

  5. Save the file (Ctrl+X, Y, Enter)

📁 What these lines do:

HiddenServiceVersion 3 explicitly selects v3 onion addresses (56-character, Ed25519-based). V3 is the current standard — stronger cryptography and longer addresses than legacy v2.

HiddenServiceDir tells Tor where to store the hidden service keys and the hostname file. Using a permanent path means your .onion address survives reboots.

HiddenServicePort 22 127.0.0.1:22 maps .onion port 22 to the MacBook’s local SSH daemon — only reachable through Tor.

Step 3: Generate Tor v3 Client Authorization Keypair

Tor v3 client authorization means your hidden service rejects all connection attempts from anyone who does not hold the matching private key — including anyone who discovers your .onion address. This is the outermost layer of security.

  1. Install coreutils via Homebrew (provides gbase32 for base32 encoding):

    brew install coreutils

  2. Generate an X25519 keypair using OpenSSL (built into macOS):

    openssl genpkey -algorithm x25519 -out ~/.tor/client_auth.priv.pem
openssl pkey -in ~/.tor/client_auth.priv.pem -pubout -out ~/.tor/client_auth.pub.pem

  3. Extract the base32-encoded private key (you will give this to Orbot on iPhone):

    openssl pkey -in ~/.tor/client_auth.priv.pem -outform DER | tail -c 32 | gbase32 | tr -d '='

    Save this output — it is your client private key (base32). You will use it in Step 11.

  4. Extract the base32-encoded public key (you will install this on MacBook):

    openssl pkey -pubin -in ~/.tor/client_auth.pub.pem -pubout -outform DER | tail -c 32 | gbase32 | tr -d '='

    Save this output — it is your client public key (base32).

🔑 Key security property: The X25519 public key is installed on the MacBook. Tor uses it to encrypt hidden service descriptor data so only the holder of the matching private key can even discover that the service exists. Your .onion address is useless to anyone else.

Step 4: Install Client Authorization on MacBook

  1. Create the server-side authorization file (replace <PUBLIC_KEY_BASE32> with the public key from Step 3):

    echo "descriptor:x25519:<PUBLIC_KEY_BASE32>" > ~/.tor/ssh_hidden_service/authorized_clients/iphone.auth
chmod 600 ~/.tor/ssh_hidden_service/authorized_clients/iphone.auth

    Example (your key will differ):

    descriptor:x25519:AAAAAABBBBBBCCCCCCDDDDDDEEEEEEFFFFFFFFGGGGGGHHHHHHIIIIIIJJJJJJ

  2. Verify the file was created correctly:

    cat ~/.tor/ssh_hidden_service/authorized_clients/iphone.auth

Step 5: Start Tor and Retrieve the .onion Address

  1. Start Tor as a background service (auto-restarts on login):

    brew services start tor

  2. Wait 15–20 seconds for Tor to bootstrap and generate the hidden service keys

  3. Retrieve your MacBook’s .onion address:

    cat ~/.tor/ssh_hidden_service/hostname

    You will see something like:

    abc123xyz456def789ghi012jkl345mno678pqr901stu234vwx567yz89.onion

  4. Copy and save this address — you will enter it into Termius on your iPhone

✅ Verify Tor is running:

brew services list | grep tor

Status should show started. If it shows error, check logs:

cat $(brew --prefix)/var/log/tor.log

Step 6: Harden SSH Configuration (Required)

⚠️ This step is required before enabling SSH. The default macOS SSH configuration accepts password authentication. Enabling Remote Login without hardening first would expose your MacBook to brute-force attacks via the Tor network.

  1. Open the SSH daemon configuration file:

    sudo nano /etc/ssh/sshd_config

  2. Find and set (or add) these directives — comment out any conflicting existing entries with #:

    ListenAddress 127.0.0.1
PermitRootLogin no
PasswordAuthentication no
ChallengeResponseAuthentication no
PubkeyAuthentication yes
AuthenticationMethods publickey
MaxAuthTries 3
LoginGraceTime 20
X11Forwarding no
AllowTcpForwarding no

  3. Save the file (Ctrl+X, Y, Enter)

🔒 What each directive does:

ListenAddress 127.0.0.1 — SSH only binds to localhost. The port is invisible on the LAN and internet. Only Tor (which connects internally via 127.0.0.1:22) can reach it.

PasswordAuthentication no and ChallengeResponseAuthentication no — completely disables password login. Only public key authentication is accepted.

AuthenticationMethods publickey — redundant confirmation; only public key accepted.

MaxAuthTries 3 — disconnects after 3 failed attempts.

LoginGraceTime 20 — closes unauthenticated connections after 20 seconds.

X11Forwarding no and AllowTcpForwarding no — minimal attack surface; no tunnelling capabilities.

Step 7: Generate Ed25519 SSH Key Pair

Ed25519 is the recommended SSH key type — faster and more resistant to side-channel attacks than RSA.

  1. Generate the key pair (on MacBook — this key pair belongs to your iPhone):

    ssh-keygen -t ed25519 -C "iphone-termius" -f ~/.ssh/iphone_ed25519

    When prompted for a passphrase, enter a strong passphrase — this protects the private key if your iPhone is lost.

  2. Install the public key in the authorized keys file:

    cat ~/.ssh/iphone_ed25519.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
chmod 700 ~/.ssh

  3. Display the private key for transfer to iPhone (you will copy this into Termius in Step 12):

    cat ~/.ssh/iphone_ed25519

    The output starts with -----BEGIN OPENSSH PRIVATE KEY-----. Copy the entire block including the header and footer lines.

⚠️ Private key security: Transfer the private key to Termius over a local connection (cable, AirDrop on your local network) whenever possible. Delete ~/.ssh/iphone_ed25519 from MacBook after transferring — the MacBook only needs authorized_keys with the public key, not the private key.

Step 8: Enable SSH on MacBook

SSH is now safe to enable because:

  • sshd_config restricts it to 127.0.0.1 (Tor-only)
  • Password authentication is disabled
  • Only the Ed25519 public key from Step 7 is accepted

  1. Open System Settings → General → Sharing

  2. Toggle Remote Login to On

  3. Confirm your user appears in the allowed users list

  4. Restart the SSH daemon to apply the hardened configuration:

    sudo launchctl stop com.openssh.sshd
sudo launchctl start com.openssh.sshd

  5. Verify SSH is only listening on localhost (not 0.0.0.0):

    sudo lsof -i :22

    You should see sshd bound to 127.0.0.1:ssh only. If you see *:ssh or 0.0.0.0:ssh, the sshd_config change has not taken effect — restart macOS and re-check.

Step 9: Install tmux on MacBook

tmux keeps your Claude Code session alive when you disconnect from SSH. Without it, closing Termius on your iPhone immediately kills the running Claude Code process.

  1. Install tmux:

    brew install tmux

  2. Verify installation:

    tmux -V

Essential tmux commands for this workflow:

  • Start a named session: tmux new -s claude
  • Detach and leave running: Ctrl+B, then D
  • Reattach from SSH: tmux attach -t claude
  • List all sessions: tmux ls

⚠️ Critical habit: Always start Claude Code inside a named tmux session. If Claude Code runs in a plain terminal and the SSH connection drops, the process is killed immediately.

📍 When to use tmux: Do not start a tmux session now. These commands are used later — after you SSH into your MacBook from your iPhone (Step 12). Once inside that SSH session, run tmux new -s claude, then launch Claude Code. You can then detach and close Termius without killing the process. For now, close this terminal and continue to Step 10.

Step 10: Install VS Code, Claude Code Extension, and Claude Code CLI

  1. Download and install Visual Studio Code from code.visualstudio.com

  2. Open VS Code

  3. Press Cmd+Shift+X to open the Extensions panel

  4. Search for Claude Code and install the official Anthropic extension

  5. Follow the setup wizard to authenticate with your Anthropic account

  6. Verify it works: Cmd+Shift+P → type Claude: Start Session

  7. Install the Claude Code CLI (needed to run claude in the terminal from your SSH session):

    curl -fsSL https://claude.ai/install.sh | bash

  8. Verify the CLI is installed:

    claude --version

Why both? The VS Code extension gives you the full GUI experience when working locally. The CLI (claude command) is what you run inside a tmux session over SSH from your iPhone — there is no GUI over a terminal connection.

Step 11: Install Orbot on iPhone and Import Client Auth Key

Orbot is the official Tor proxy app for iOS. In VPN mode it routes all iPhone traffic through Tor — including Termius SSH connections. You must also import the Tor v3 client authorization private key so Orbot can authenticate to your hidden service.

  1. On your iPhone, open the App Store

  2. Search for and install Orbot (free — by Guardian Project / Tor Project)

  3. Open Orbot → tap Start

  4. Enable VPN Mode (toggle in Orbot’s main screen)

  5. Wait for Orbot to show Connected

  6. Import the Tor v3 client authorization key:

    • Tap the gear icon in the top-right corner of Orbot’s main screen
    • In the pop-up menu, tap Auth Cookies
    • Tap + to add a new entry
    • Enter your MacBook .onion address from Step 5
    • Enter the base32 private key you saved in Step 3
    • Tap Save

    Note: Older guides show Settings → Onion Services → Client Authorization — that path no longer exists. Auth Cookies is now in the gear icon dropdown on the main screen.

📡 VPN Mode is required: Without VPN mode, iOS apps cannot resolve .onion domains. With VPN mode active, Orbot intercepts all DNS lookups and routes .onion connections through Tor automatically.

🔑 Client auth is required: Without the imported private key, Tor returns an empty descriptor for your .onion address — Termius will time out as if the service does not exist. This is the intended behavior.

Step 12: Install Termius on iPhone and Connect with Ed25519 Key

  1. On your iPhone, open the App Store

  2. Search for and install Termius (free — basic SSH included in the free tier)

  3. Confirm Orbot is running in VPN mode before attempting to connect

  4. Import your Ed25519 private key into Termius:

    • Open Termius → Settings → Keychain → + → New Key
    • Paste the full private key content from Step 7 (the -----BEGIN OPENSSH PRIVATE KEY----- block)
    • Enter the key passphrase you set in Step 7
    • Save as iphone-termius

  5. Create a new host in Termius → tap New Host

  6. Fill in:

    • Hostname: your MacBook .onion address from Step 5
    • Port: 22
    • Username: your macOS username
    • SSH Key: select iphone-termius (the key imported above)
    • Password: leave blank — password auth is disabled on the server

  7. Tap Save → tap the host to connect

⏱️ Expected connection time: 10–20 seconds. Tor v3 circuit setup with client authorization takes longer than a plain connection — Tor is negotiating three relay hops and verifying your client authorization before the SSH handshake begins. Once connected, interactive SSH is responsive enough for approving Claude Code actions.

Step 13: Install ntfy on iPhone

ntfy sends push notifications from MacBook to iPhone whenever Claude Code is about to take an action or finishes a session.

  1. On your iPhone, open the App Store

  2. Search for and install ntfy (free — by Binwiederhier)

  3. Open ntfy → tap + → Subscribe to topic

  4. Enter a long, random topic name (e.g., claudecode-j7k2x9m4p3) — this acts as a private channel without needing an account

  5. Tap Subscribe

🔒 Topic privacy: Anyone who knows your topic name can subscribe. Use a long random string (16+ characters) that cannot be guessed. Never reuse a topic name across devices or share it publicly.

Step 14: Configure Claude Code Hooks for Notifications

  1. On your MacBook, open Terminal and edit the Claude Code settings file:

    mkdir -p ~/.claude
nano ~/.claude/settings.json

  2. Add the following (replace your-topic with your ntfy topic name from Step 13):

    {
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "curl -s -d \"⚙️ About to run: $CLAUDE_TOOL_NAME\" ntfy.sh/your-topic"
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "curl -s -d \"✅ Claude Code session finished\" ntfy.sh/your-topic"
          }
        ]
      }
    ]
  }
}

  3. Save (Ctrl+X, Y, Enter) and restart Claude Code for hooks to take effect

📱 What you will see on iPhone: Every time Claude Code is about to run a Bash command, write a file, or edit code, your iPhone buzzes with a notification. When the session finishes, you get a completion ping — your cue to open Termius and give an approval or new instruction.

Step 15: End-to-End Test

  1. On MacBook — navigate to your project folder, then start Claude Code inside a tmux session:

    cd ~/path/to/your-project
tmux new -s claude
claude

    💡 Tip: Always cd into your project directory before starting tmux. Claude Code uses the working directory as context — launching from the right folder means it immediately sees your codebase without needing to navigate later.

  2. Detach — press Ctrl+B, then D. Claude Code keeps running in the background.

  3. On iPhone — confirm Orbot is connected (VPN badge visible in status bar) and the client auth key is imported (Step 11)

  4. Open Termius → tap your .onion host → wait 10–20 seconds for the Tor connection to establish

  5. Reattach to the session:

    tmux attach -t claude

  6. You are now live in the same Claude Code session from your iPhone

  7. Test notifications — trigger any tool use in Claude Code and verify ntfy fires on your iPhone within seconds

Step 16: End a Session and Stop All Services

When you are done working, stop all services that expose attack surface. Running Tor and SSH continuously when not in use is unnecessary risk.

On iPhone:

  1. Close the Termius SSH session (Termius needs no special shutdown — closing the connection is enough)
  2. ntfy needs no action — it is a passive notification receiver and can stay open
  3. Open Orbot → tap Stop to disconnect from Tor
  4. Disable VPN mode

On MacBook — stop Tor and SSH:

# Detach from tmux first if still attached (Ctrl+B, D), then:

# Stop Tor hidden service
brew services stop tor

# Stop SSH listener
sudo launchctl stop localhost.ssh
sudo launchctl unload /Library/LaunchDaemons/localhost-ssh.plist

Verify nothing is listening on port 22:

sudo lsof -i :22

Expected: no output.

To start a new session later:

Follow these steps in order:

  1. On MacBook — start SSH and Tor:

    sudo launchctl load /Library/LaunchDaemons/localhost-ssh.plist
brew services start tor

  2. On iPhone — open Orbot → tap Start → enable VPN mode. Wait until Orbot shows a green connected state.

  3. On iPhone — open ntfy → confirm your topic channel is still subscribed (no action needed beyond verifying it is open).

  4. On iPhone — open Termius → tap your saved host → connect. You should land at the MacBook shell prompt.

  5. On iPhone (in Termius) — reattach to your existing tmux session:

    tmux attach -t claude

    Or start a new one if the previous session was closed:

    cd ~/path/to/your-project
tmux new -s claude
claude

⚠️ Reboot behaviour: After a reboot, neither SSH nor Tor start automatically — you must run the start commands above before connecting. Verify with sudo lsof -i :22 and brew services list | grep tor before attempting to connect from iPhone.

Verify who is connected before ending a session:

# Show all active SSH sessions — who is logged in and from where
who

# Show open SSH connections with source address (will show 127.0.0.1 for Tor connections)
sudo lsof -i :22 -n -P | grep ESTABLISHED

# Full SSH session detail: user, PID, login time, source
last | head -10

Expected output for a legitimate Tor-only session:

  • who shows your own username with a pts/ or ttys terminal
  • lsof shows 127.0.0.1:22 → 127.0.0.1:<ephemeral-port> (ESTABLISHED) only while an SSH session is actively open — no output means no active remote connection, which is normal
  • last shows two kinds of entries: logins from 127.0.0.1 (SSH from iPhone via Tor) and logins with no IP address (local Terminal or VS Code sessions on the MacBook itself) — both are expected and legitimate

🔍 What to look for: Since SSH is bound to 127.0.0.1 and only reachable via the Tor hidden service, any ESTABLISHED connection on port 22 originated through Tor. A connection from any address other than 127.0.0.1 would indicate the SSH listener is unexpectedly exposed — stop sshd immediately and re-check your launchd plist.

🔑 Why malicious connections are structurally prevented: An attacker would need (1) your .onion address, (2) the X25519 client auth private key, and (3) the Ed25519 SSH private key with its passphrase — all three independently. The Tor client auth layer means the hidden service is invisible without the key, so port scanning or address brute-forcing cannot reach the SSH layer at all.

Troubleshooting

Tor hidden service hostname file not found

  • Confirm the HiddenServiceDir path in torrc exactly matches the directory you created
  • Confirm permissions: chmod 700 ~/.tor/ssh_hidden_service
  • Check Tor logs: cat $(brew --prefix)/var/log/tor.log
  • Restart Tor: brew services restart tor

Termius times out connecting to .onion address

  • Confirm Orbot is running in VPN mode — the VPN badge must be visible in iPhone status bar
  • Confirm the Tor v3 client auth private key is imported in Orbot (Step 11) — without it, the hidden service is invisible
  • Allow 10–20 seconds — Tor v3 with client auth has a longer circuit setup time
  • Verify Tor is running on MacBook: brew services list | grep tor

Termius reports “connection reset by peer”

This error means Tor reached port 22 on the MacBook successfully but the SSH daemon immediately dropped the connection. It is distinct from a timeout (Tor/auth issue) and from “connection refused” (sshd not running). Work through these checks in order:

  1. Validate sshd_config for syntax errors:

    sudo sshd -t

    Any error printed here will cause sshd to reset every incoming connection. Fix the reported line, then restart sshd (see Step 8 or reload the custom plist).

  2. Confirm SSH host keys exist:

    ls /etc/ssh/ssh_host_*

    Expected: files like ssh_host_ed25519_key, ssh_host_rsa_key, etc. If the directory is empty, regenerate them:

    sudo ssh-keygen -A

  3. Check live sshd logs for the reset reason:

    sudo log show --predicate 'process == "sshd"' --last 5m --style compact

    Look for lines like error: Bind to port 22, error: Could not load host key, or authentication-related messages.

  4. Test SSH locally from the MacBook itself:

    ssh -v -i ~/.ssh/iphone_ed25519 localhost

    If this succeeds, the problem is on the Tor/iPhone side. If it fails with the same “reset” message, the issue is in the local sshd configuration.

  5. Verify the custom launchd plist is loaded (if you went through the ListenAddress fix):

    sudo launchctl list | grep localhost.ssh

    Expected outputs:

    12345    0    localhost.ssh   ← running normally (PID, exit code 0)
-        0    localhost.ssh   ← loaded but idle, this is fine
-      255    localhost.ssh   ← loaded but sshd crashed on last start

    No output at all means the plist is not loaded — reload it:

    sudo launchctl load /Library/LaunchDaemons/localhost-ssh.plist

    If you see exit code 255, sshd launched but crashed immediately. Diagnose in order:

    # 1. Check sshd_config for syntax errors
sudo sshd -t

# 2. Check if port 22 is already claimed by another process
sudo lsof -i :22

# 3. Check the crash reason in logs
sudo log show --predicate 'process == "sshd"' --last 5m --style compact

    Fix whatever the log reports (bad config line, port conflict, missing host key), then unload and reload the plist:

    sudo launchctl unload /Library/LaunchDaemons/localhost-ssh.plist
sudo launchctl load /Library/LaunchDaemons/localhost-ssh.plist

  6. Confirm Remote Login is still enabled in System Settings → General → Sharing. macOS may re-disable it after a system update or preference reset, which stops sshd from being managed by launchd at all.

SSH connection refused

  • Confirm Remote Login is enabled: System Settings → General → Sharing → Remote Login
  • Check sshd is running: sudo launchctl list | grep ssh
  • Verify SSH is listening on 127.0.0.1 (not 0.0.0.0): sudo lsof -i :22

SSH still listens on *:ssh after adding ListenAddress 127.0.0.1

On macOS, launchd binds the SSH socket before passing it to sshd, so ListenAddress in sshd_config is ignored — launchd wins. The fix is a custom launchd plist that binds to 127.0.0.1 and replaces the system-managed socket.

  1. Create /Library/LaunchDaemons/localhost-ssh.plist:

    sudo tee /Library/LaunchDaemons/localhost-ssh.plist > /dev/null << 'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>localhost.ssh</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/sbin/sshd</string>
    <string>-i</string>
  </array>
  <key>Sockets</key>
  <dict>
    <key>Listeners</key>
    <dict>
      <key>SockFamily</key>
      <string>IPv4</string>
      <key>SockNodeName</key>
      <string>127.0.0.1</string>
      <key>SockServiceName</key>
      <string>ssh</string>
      <key>SockType</key>
      <string>stream</string>
    </dict>
  </dict>
  <key>inetdCompatibility</key>
  <dict>
    <key>Wait</key>
    <false/>
  </dict>
  <key>StandardErrorPath</key>
  <string>/dev/null</string>
</dict>
</plist>
EOF

  2. Unload the system plist and load the custom one:

    sudo launchctl stop com.openssh.sshd
sudo launchctl unload /System/Library/LaunchDaemons/ssh.plist 2>/dev/null || true
sudo launchctl load /Library/LaunchDaemons/localhost-ssh.plist

  3. Verify:

    sudo lsof -i :22

    Expected output: sshd ... TCP localhost:ssh (LISTEN) — not *:ssh.

After a reboot, confirm with sudo lsof -i :22 that the binding held. If the system plist reloads, ensure Remote Login remains disabled in System Settings → General → Sharing so macOS does not re-activate com.openssh.sshd.

SSH public key authentication fails

  • Verify ~/.ssh/authorized_keys contains the correct public key: cat ~/.ssh/authorized_keys
  • Check permissions: chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
  • In Termius, confirm the correct key (iphone-termius) is selected for the host, not password auth
  • Confirm the key passphrase entered in Termius matches the passphrase set during key generation

tmux session not found after SSH

  • Run tmux ls — if empty, start fresh with tmux new -s claude
  • Always start Claude Code inside a named tmux session

Tor not running after MacBook reboot

  • Re-run: brew services start tor
  • Confirm it is in the services list: brew services list | grep tor

ntfy notifications not arriving on iPhone

  • Test manually from MacBook: curl -d "test" ntfy.sh/your-topic — should appear on iPhone immediately
  • Verify topic name in settings.json exactly matches the subscribed topic in the ntfy app
  • Restart Claude Code after editing settings.json
